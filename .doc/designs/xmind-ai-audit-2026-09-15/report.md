# XMind AI 参考优化与真实链路验收

审查日期：2026-09-15

## 1. 证据与边界

- 参考证据：[XMind AI 首页](./01-xmind-ai-home.png)。仅观察用户已登录 Chrome 中可见的交互和布局，没有向 XMind 提交提示词、脑图或任何业务数据。
- 本地证据：[AI 对话与实时脑图](./02-local-ai-conversation.png)。用于核对左侧 Agent 交互记录、右侧实时画布和底部持续输入器。
- 本次复用 XMind 的高层产品模式，不复制其商标、专有图标、素材、源码或私有模型行为。
- 后续通过本地应用内浏览器接管 `#130` 的真实登录会话，完成 Agent 选择、提案冲突、覆盖确认、权威重载与已应用状态的端到端复核；截图均来自该次真实运行，不以源码状态替代浏览器证据。

## 2. 本轮产品改进

### 2.1 生成过程和移动端实时预览

- 桌面端继续采用约 500px 的左侧 AI 工作台，保留右侧唯一权威脑图画布。
- 左侧按时间展示用户要求、状态、工具开始/完成/失败、草稿版本和最终结果；不展示模型隐藏思维链。
- 小于等于 760px 时不再永久隐藏实时脑图。任务运行中或草稿可用时，顶部出现“实时脑图”按钮，可切换到全屏预览，再通过“返回 AI 对话”回到交互记录。
- 移动端切换按钮包含 `aria-controls`、动态 `aria-label` 和 `aria-pressed`；关闭窗口或新建对话时清理预览状态。

### 2.2 Native Agent 终态可靠性

- 新增正式 `request_clarification` 工具，只允许 Agent 在任何草稿副作用之前提出 1 至 3 个问题；请求澄清和完成 Artifact 都是终态，终态后再调用工具会失败关闭。
- 针对 Ollama 偶尔忽略工具而直接输出问句的行为，增加严格自由文本兼容：整段输出必须全部是 1 至 3 行有效问句，拒绝说明、JSON、代码、URL、敏感信息索取、纯标点和纯表情都不会被误判为澄清。
- 针对 Ollama 完成节点修改却漏调机械终态工具的行为，Native Adapter 1.11.0 增加受限自动收口：
  - 已校验且之后未修改，只补 `complete_artifact`；
  - 从未校验但已有成功草稿变更，由平台补做 `validate_draft` 和 `complete_artifact`；
  - 校验后又修改，仍按无效结果拒绝。
- 自动收口只生成待用户确认的文件或提案，不会自动应用到当前脑图。

### 2.3 Connector 可信状态

- 一致性报告现在与 Agent manifest 的 Adapter、SDK、Runtime、工具合同、错误合同和 SMM 版本逐项比较。
- 版本变化或旧报告缺字段时，管理页显示“版本变化，需重检”，并把 `releaseEligible` 置为 `false`，不再用旧通过记录冒充当前版本通过。
- Native 1.11.0 的确定性合同检查已重新执行并通过；该检查明确标记 `providerExecution=not_run`，不等同于真实提供商发布验收。

### 2.4 讨论结果事务边界

- 新增服务级原子性回归：成功时纯文本 Response、`completed_message` Job、Session 和 `message_ready` 事件只提交一次；提交失败时全部回滚，不留下半完成消息、Artifact 或 Proposal。

### 2.5 多轮编辑 / 讨论切换与独立脑图续写

- 终态任务现在可以在同一平台会话中逐轮切换“编辑脑图”和“讨论内容”；当前轮结果展示与下一轮交互模式被拆开，切换下一轮模式不会隐藏当前提案或文字回答。
- `/messages` 继续接口新增受白名单约束的下一轮 `intent`。后端根据本轮意图重新派生 `message / proposal / file`，不再固定继承首轮输出类型。
- 编辑和讨论之间切换时保留平台会话与可见历史，但不恢复上一轮 Provider SDK Session，避免无工具文字会话与可写脑图工具会话串用。
- 修复“新建脑图后继续调整”必然失败的问题：生成 Artifact 会被规范化为合法的 `uploaded_artifact + document` 来源，不再构造非法的 `none + document`。
- 历史 Artifact 只作为本轮内容来源，`parentJobId` 始终指向真实上一轮；不会再因为选中历史结果而跳过中间讨论轮次。
- 已另存为云端文件的 `completed_file` 结果也可以继续生成。

### 2.6 应用 / 撤销后的云端权威续写

- `applied / undone` 云端任务新增显式 `continuationBase=current_document` 合同；普通完成结果继续沿用不可变 `artifact`，两类语义不再混淆。
- 发起续写前，浏览器先结算同一脑图尚未完成的应用/撤销恢复记录，确认用户仍打开原脑图，并刷新编辑器上下文。
- 服务端重新鉴权并读取当前云端正文，冻结新的 `revision / documentHash / roomEpoch`，且令 `document == baselineDocument`；新 Proposal 不再绑定应用前旧基线，也不会从已撤销 Artifact 重新起步。
- 父任务在读取来源与加锁之间发生 `applied → undone` 等状态竞态时零写入拒绝，用户刷新后再试。
- 应用或撤销完成后，前端同步刷新并持久化来源上下文，避免页面恢复时拼出“新正文 + 旧 revision/hash”的混合状态。

### 2.7 只读协作者 AI 入口

- AI 工作台改为由始终挂载的编辑器壳持有唯一实例，不再依赖仅编辑态出现的 Toolbar。
- 左侧工作区活动栏新增权限受控的 AI 入口；只读协作者可基于可读脑图生成独立 AI 文件，但仍不能形成可回写云端的 Proposal。

### 2.8 加密持久草稿 checkpoint 与恢复代际

- `draft_initialized / draft_changed` 现在把每个任务的最新草稿写入数据库 checkpoint，并与不含正文的 SSE 事件元数据同事务提交；文档、操作和初始帧均以带 `cryptoVersion / keyId` 的认证密文持久化，明文不进入事件表或日志。
- 数据库 checkpoint 是最新草稿的权威来源，Redis 只保留短 TTL 历史帧并作为可丢弃读缓存；最新缓存帧缺失、过期或与 checkpoint 坐标/哈希不一致时，读取链路从数据库恢复并尝试回填 Redis。
- 服务恢复未完成任务时会解密并校验 checkpoint 的任务、版本、`previewEpoch`、哈希和有效期；恢复成功后保留可见草稿，发出 `generation_restarted`，并以新 Provider turn 继续，不伪装成旧 SDK Session 续跑。
- 每次重启执行都分配更高的 `previewEpoch` 和不回退的全局预览版本；任务 `executionEpoch` 与租约双重围栏使失去所有权的旧 worker 无法迟到写入 checkpoint 或 Redis，相同坐标却哈希不同的帧也会被拒绝。

### 2.9 本地应用 / 撤销后的当前快照续写

- 本地工作区的 `applied / undone` 任务现在可以用 `continuationBase=current_snapshot` 续写。浏览器先结算本地应用/撤销回执，重读服务端父任务状态，再对编辑器中的 `documentId / revision / documentHash` 做稳定性复核后提交当前文档。
- 服务端只接受本轮由浏览器持有的文档字节、revision 和声明哈希，文档身份与 scope 继续使用已授权的原始本地血缘；客户端传入的 baseline、云端脑图身份、`roomEpoch` 或历史 Artifact 不会被当作新基线。
- 正文会在服务端重新规范化、计算哈希和冻结，创建新任务前还会按稳定顺序锁定会话任务并复核父任务身份、Proposal 与 `expectedParentStatus`；读取期间发生的文档或 `applied ↔ undone` 竞态均在写入前拒绝。
- `POST /mindmap/ai/jobs/{jobId}/messages` 新增路由级请求体上限：明文最多 2,128,000 字节，传输加密包最多 3,000,000 字节；同时检查 `Content-Length`、分块累计大小和解密后明文，超限在创建 Job 前返回 `413 / AI_INPUT_TOO_LARGE`。

### 2.10 富文本初始化与云端同步闭环

- 复现并定位了验收脑图 `#130` 在用户没有操作时每约 2 至 3 秒自动提交 10 个节点的问题。根因不是协作服务器主动产生内容，而是 `plain + HTML` 节点在 RichText 初始化时被转换，`resetRichText` 等渲染过渡态又被误记入历史并提交；服务端只持久化了 `text`，没有同步持久化 `richText`，权威回载后再次触发转换，形成保存—重载反馈环。
- 缺失 `smmVersion` 不再自动等同于旧版文档；只有明确低于 `0.13.0` 的版本才走 legacy reset。缺版本但已经标记为富文本的规范 HTML 连续载入保持字节级稳定。
- 首帧完成前禁止正文变更跟踪和 Yjs 提交；首帧完成后取消延迟历史任务并建立静默基线，初始化归一化不再伪装成用户编辑。
- HTTP operation 与 Yjs 统一剥除 `isActive / inserting / needUpdate / resetRichText / activeStyle`，这些本地选择、插入和渲染状态不会进入云端正文。
- 服务端把 `text` 与 `richText` 作为同一原子持久化和冲突域：正文变化会同时写入格式标记，切回纯文本也会删除旧的富文本标记。

### 2.11 Agent 选择主权与提交门禁

- Agent 下拉层级已提升到 AI 工作台之上，Codex、Claude Code 与 Native 选项均可见、可点击，不再被抽屉遮挡。
- 用户选定 Agent 后，切换“编辑/讨论”、当前脑图/新建脑图或任务类型只重新校验能力，不再静默替换用户选择；仅首次没有任何选择时默认 Native。
- 已选 Agent 缺失、被禁用或与当前任务不兼容时，界面保留原选择并展示具体原因和“选择 Agent”入口，同时关闭发送门禁，避免请求落到错误 Agent。
- Agent 选项、状态原因与能力披露支持长文本换行，设置区不再产生横向滚动条。

### 2.12 新建脑图结果的产品内去向闭环

- 使用 Native Agent 创建了隔离的新脑图任务 `198442e7-c5f7-4a4e-b32f-e3081a40545b`，实时过程从排队、创建根节点、工具约束修正、分批新增节点、统一校验推进到 Artifact 就绪；最终为 13 个节点、变化版本 12，当前云端脑图未被修改。
- 运行态审查发现“打开副本”和“另存云端”虽然存在于源码，却被包在没有结构指令的原生 `<template>` 元素中；浏览器实际尺寸为 `0×0`，结果页因此只剩“下载 .smm”，产品内工作流被截断。
- 移除失效的 `<template>` 容器后，结果页稳定展示“下载 .smm”“打开为本地脑图”“保存为云端脑图”三个动作；云端保存作为主要去向突出显示，所有动作高度统一为 30px，避免继续呈现为难以识别的小号文字链接。
- 页面刷新并恢复任务后，三个动作仍可见且可用；“保存为云端脑图”能够打开带默认标题的命名对话框。验收中已取消确认，没有创建额外云端文件。

### 2.13 协作版本冲突后的确认覆盖

- 云端普通提案的差异勾选现在就是明确的整图覆盖授权，文案直接说明“用 AI 完整结果覆盖当前脑图（可撤销）”；主按钮同步改为“覆盖当前脑图”，不再先尝试普通合并、报版本冲突后再要求第二次确认。
- 用户点击主按钮的第一次请求即使用独立幂等键持久化 `forceOverwrite` 意图。服务端先读取最新权威正文作为撤销基线，再在协作排空与 CAS 围栏内校验冻结 Proposal/Artifact，并用已校验 Artifact 整体替换当前内容；确认期间仍出现的新并发写入会继续失败关闭，并提示再次点击覆盖，而不是误导用户重新生成提案。
- 覆盖回执会把 `forceOverwrite` 贯穿到编辑器最终重载：旧 revision 上未发送的正文、元数据和视图意图被作废，通用 `document_reset` 的一次性保护阻塞被解除，然后直接加载不低于回执 revision 的最新权威文档。只有画布、revision 和协作源全部收敛后才删除浏览器恢复记录。
- 自动标记和其他无人值守路径不会自动使用强制覆盖；它们仍执行安全字段增量应用，版本冲突时不会覆盖协作内容。

### 2.14 Native Agent 引用、断点续跑与失败熔断

- 复盘任务 `971fd10a-d93b-469a-8a06-f1854b737e39` 的 80 条事件后确认：模型使用 `@root` 新增一级节点，但 Native Schema 明确禁止该引用；后端又只返回通用约束错误，导致模型在同一错误上循环。开发期间服务重载后，检查点草稿已存在，但继续轮次仍暴露并要求 `start_document`，进一步产生确定性失败。
- Native Adapter 1.12.0 为每个任务建立安全的节点引用表：`@root` 会解析为本任务根节点，成功的 `clientRef` 可跨工具轮次继续引用，重复别名和未授权 UID 仍失败关闭。
- 恢复任务会从持久草稿提取根节点引用，隐藏 `start_document` 工具，并明确要求先读取投影后继续，不会因恢复而重建整棵树。
- 草稿约束错误现在转换为脱敏且可执行的固定指引，区分根节点/父节点引用、重复别名、草稿已存在和配额超限；左侧生成过程直接显示这些原因与是否可重试。
- 同一脱敏错误第 3 次或本轮第 6 次可恢复失败时立即停止，最后一条记录标记为不可重试；Agno 工具调用上限同步收紧为 32，简单任务不再可能静默循环数百秒。

### 2.15 首节点等待反馈与 Ollama 模型保温

- 运行时证据确认任务创建后约 1 秒即进入 `running / 25%`，约 20 秒的首节点空白发生在 Ollama 首次加载与第一轮工具推理，不是调度队列阻塞；`agent_started` 等生命周期事件会被安全缓冲到首个草稿副作用后再发布，因此不能把该事件的可见时间误判为 Agent 真正启动时间。
- 实时脑图在首个节点出现前不再只显示静态“正在准备”占位，而是按耗时推进“正在理解你的要求”“正在准备脑图结构”“本机模型正在生成首个节点”，同时显示已等待秒数、首次本机模型 10–30 秒预期和“请勿重复提交”提示。
- 等待状态使用 `role=status / aria-live=polite`，耗时数字不进入实时朗读；动效遵守 `prefers-reduced-motion`。首个草稿出现后自动切换回真实脑图与变化版本，不制造虚假进度。
- Native Ollama 在管理员没有显式配置时默认设置 `keep_alive=30m`，使连续任务复用已加载模型；字段级或 `request_params` 中的自定义保温时间保持优先，不改变非 Ollama 模型。

### 2.16 输出语言与目标布局契约

- “任务与 Agent 设置”新增输出语言和目标布局。语言支持简体中文、繁體中文、English、日本語和한국어；布局复用编辑器已有结构体系，提供思维导图、逻辑结构图、组织结构图、目录组织图、时间轴和鱼骨图。
- 当前脑图第一次打开时自动采用其真实布局；上传文件采用文件布局；新建脑图默认逻辑结构图。用户选择会进入任务恢复、最近任务默认值和正式重试请求，现有任务运行后保持锁定。
- 分支、已选节点等局部授权范围禁止修改整图布局，提交时也会强制使用当前布局；AI 自动标记同样只补测试用例标签，不改变结构布局。界面直接解释这一限制。
- 服务端不再只依赖自由文本参数：语言代码按受控 BCP 47 子集校验并规范大小写，布局只接受引擎白名单。Native、Codex SDK、Claude Code SDK 共用语言/布局输出契约；新建或整图任务在冻结 Artifact 前再次确定性校正目标布局。
- 为避免已通过一致性测试的 Connector 因实现升级突然不可选，三类 Agent 保持已发布 Adapter 版本，只将 Prompt 版本分别推进到 `mindmap-agent-12`、`codex-mindmap-8` 和 `claude-mindmap-6`，使新产物仍可追踪契约版本。

### 2.17 Agent 连接就绪度与首次运行反馈

- Agent 选择不再把 SDK、认证、区域、保留策略和运行边界压进固定 66px 的内部滚动区。页面先展示“连接已就绪 / 首次运行前检查 / 当前不可用”，详细技术披露改为按需展开，用户可以先完成选择再决定是否查看治理信息。
- 下拉选项直接显示每个 Agent 的连接状态；切换 Claude、Codex 或 MindMap Agent 后，状态卡同步显示最近检查时间或下一步动作。不可用与不支持当前任务仍保持禁用，不会自动替换用户选择。
- Connector 的 `healthy` 结果新增默认 15 分钟有效期，并可通过 `MINDMAP_AI_CONNECTOR_HEALTH_TTL_SECONDS` 配置。过期状态在能力清单中只读降级为 `unknown`，不再把数小时前的检查误报为当前连接正常；任务创建时会重新探测并刷新结果。
- 首次健康检查或任务创建尚未返回时，输入器显示当前 Agent、所处阶段和已等待秒数，并使用 `role=status / aria-live=polite` 持续反馈，避免用户因只看到发送按钮旋转而重复提交。

### 2.18 历史版本冲突记录升级为直接覆盖

- 云端普通 Proposal 的差异确认继续作为整图覆盖授权，首次请求携带 `forceOverwrite=true` 并以独立幂等键执行；服务端在协作栅栏内改绑最新 revision，把点击时的当前权威正文保存为撤销快照，再写入完整 AI Artifact。
- 修复了升级前遗留恢复记录的兼容死角：旧客户端若已将普通应用保存为 `AI_APPLY_CONFLICT` 或 `AI_PROPOSAL_STALE` 永久失败，新版“覆盖当前脑图”会在用户再次明确确认后，把同一用户、任务、脑图、Proposal 和冻结基线的旧记录原子升级为覆盖请求，不再要求清除记录或重新生成。
