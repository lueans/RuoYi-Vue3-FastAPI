# 脑图评论链路审计记录

审计对象：本地脑图编辑器中的评论入口、节点定向评论、发布草稿、回复/线程操作、已解决线程重开。

## 逐步结论

1. **评论入口与空编辑器**：入口与筛选结构清晰；未选择节点时会明确禁用“当前节点”，权限尚未确认时不提前显示只读状态。
2. **节点定向编辑器**：目标节点名称在编辑器顶部可见；工具栏切换导致画布短暂失焦时，仍保留最后选中的节点作为评论目标。
3. **可发布草稿**：每个节点独立保存草稿，切换节点不会把 A 节点内容误发到 B 节点；发布按钮状态与内容同步。
4. **回复与线程操作**：回复、解决、删除具备独立的操作中状态；单个请求不会锁死整个侧栏，失败时保留输入并显示就地错误。
5. **已解决线程**：文案明确说明“回复并重新打开”，降低状态变化的意外感；也保留直接“重新打开”操作。

## 可靠性优化

- 创建评论和回复均携带稳定的幂等键；网络失败后的同内容重试沿用原键，成功或内容变化后才换键。
- 服务端以“作者 + 幂等键”唯一约束兜底，并校验同键请求意图；重复请求返回原结果，不重复落库。
- 发布成功与列表刷新解耦：评论成功不会因为随后刷新失败而被误报为发布失败。
- 删除支持重试幂等，重复删除返回已删除状态。
- 追加分页按线程 ID 去重，避免翻页期间因数据变化产生重复线程。

## 可用性与无障碍

- 主要图标按钮触控目标增至 32px，并补充可读标签与忙碌状态。
- 不再把整列评论设为 `aria-live`，改用独立、礼貌播报的隐藏状态区，避免刷新列表时重复朗读全部内容。
- 删除确认会区分“整条线程”与“单条回复”，让影响范围可预期。

## 证据边界

- 真实写入 E2E 仅操作带唯一标记的测试线程，并在结束时通过产品删除流程完成软删除；未修改任何真实评论。
- 截图刻意避开了页面中的敏感评论内容。
- 本次未做真实屏幕阅读器走查，也未模拟浏览器层面的断网超时；这两项仍适合作为上线前人工验收项。
