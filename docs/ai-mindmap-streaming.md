# AI 脑图流式展示契约

## 单一展示写入者

云端是正文真源。SSE 通知携带 `previewEpoch / previewVersion`，浏览器拉取对应草稿后仅更新目标文档，不直接覆盖可见脑图。

`云端通知 → 最新目标 → 串行帧规划 → 已显示文档 → 渲染器`

- 请求创建、重试或继续云端编辑前，先获取画布所有权并锁定人工编辑、保存入口，捕获显示基线。返回任务 ID 后采用同一会话，不重新采集基线。
- 全新、尚未发送的请求先进入独立的准备门闩：同步提交活动输入，冻结新交互，但允许既有人工修改和视图保存排空；必要的权威重载完成后才捕获 AI 基线。排空失败不建立播放会话，不通过云端回源清除未保存输入。持久化未知请求恢复及重复 `start` 不走这条普通保存路径，终态校准也不得丢弃残余人工保存意图。
- 同一会话重复 `start` 是幂等操作；旧任务的结束/清理消息不能清除当前会话。
- 所有权绑定具体 `jobId / preparationId`，不由面板显隐或当前选中会话推导。关闭只是隐藏，重开恢复同一面板；存在运行任务、准备请求或未校准画布时不能重置/切换任务。
- 任务中心与深链共用会话切换入口，不以面板显隐决定是否切换。新任务通过账号、路由和云端归属校验后才接纳；新恢复指针写入成功前不清除旧指针，迟到请求不能覆盖后续选择。
- 播放期间，Yjs 文档应用、revision 通知与 HTTP 回源不能成为第二个画布写入者。
- 历史版本预览、导入、迟到的保存合并响应也服从同一门闩；开始 AI 编辑前必须结束已有历史/导入事务。
- SSE 的世代优先于版本游标；重启后的小游标有效，旧世代在途快照不能覆盖新世代。

## 帧与渲染

`mindmap-ai-live-preview.js` 每次只选择一个节点，按完整字素推进一个字符。已存在的未轮到节点保留原内容，新增节点尚未轮到时不进入展示树。移动或删除不允许绕过队列暴露整批新文字。改名按共同前缀推进，不能拿旧文字长度作为新文字播放进度。富文本截取文本节点，不能截断 HTML 字符串。

结构操作具有依赖：已有子树要移到新父节点时，必须等目标祖先链可见，再原子迁移。此前保留原位置和必要的旧容器，不能先删除已有节点再把它当新增节点重新打字。

`mindmap-ai-playback-pacing.js` 在每个新目标到达时估算剩余字素，后续只在成功帧 ACK 后递减。小积压保留自然节奏，大积压、长时间未排空或终态会降低帧间隔；每帧始终只有一个节点的一个字素，不增大字符预算、不跳到全文。目标替换不能重置队列年龄；排空后才重新计时。实际速度仍受浏览器渲染与后台节流限制，不承诺固定秒数完成。

`mindmap-ai-presentation.js` 负责唯一的渲染入口：

- 节点数据始终保存当前前缀，完整目标只传给离屏测量钩子。
- `nodeCreateContents.js / textReveal.js` 在文字挂到可见画布前遮住后缀，保留最终宽高、换行和富文本格式。
- 后续字符原地更新文字，保持节点组、连线、视口和排版尺寸；仅结构或目标尺寸变化才重新布局。
- 只读渲染仍维护节点比较快照；它是渲染元数据，不是人工编辑历史。
- 渲染超时是失败，不能当成成功 ACK 后继续播放。
- 折叠祖先通过渲染器的临时展开集合参与布局，不修改正文中的 `expand`。同一轮的后续结构帧保留该集合，避免反复折叠/展开；AI 聚焦只移动视口，不调用会修改祖先展开数据的导航命令。
- 布局与异步节点绘制属于同一个可取消渲染事务。异常或超时必须终止旧回调、复位忙碌标记，并让重试重建一致的运行时；不能只拒绝外层 Promise，留下永远等待的渲染器。
- 结束时显式等待临时展开状态清理及恢复布局，再释放编辑权限。旧会话的绘制、清理和聚焦回调均不能影响后继会话。

## 结束与恢复

完成、失败或取消后，最终 HTTP 正文也是一个播放目标：补齐漏收的变化，等待队列完成，再以同一份云端快照校准正文、文档配置、历史、节点 revision 与 Yjs 基线。保留用户当前视口，成功后恢复人工编辑及细粒度跟踪。

- direct 会话禁止通用 `clear / accepted / revert` 写入正文或释放画布。唯一正常出口是 `authoritative-target → 流式排空 → direct-committed`。
- `authoritative-target` 返回任务会话绑定的 `targetToken`。只有 token 匹配、没有在途渲染且已显示正文等于该目标时才允许提交；旧异步回调不能修改或释放新会话。
- 暂停是显示控制，不阻止终态收敛。内部排空直接恢复播放，不复用取消期间禁用的按钮权限；长时间无进展进入可重试错误态，不能无限等待或强制解锁。
- 时间线展示去重与终态处理互相独立。时间线、SSE、轮询、EOF、恢复和取消均进入同一个按任务与恢复代次隔离的终态协调器；同一任务的并发触发共享在途加载，资源或终态变化再串行处理。最终资源加载失败使用有界重试和显式恢复入口，不因历史事件先到而跳过结果加载，也不能停止已交接子任务的连接。
- 刷新/返回 direct 任务，以当前云端检查点作为恢复基线；AI 自己推进的 revision 不应与最初 `baseRevision` 比较后误判为外部冲突。
- 恢复运行中 direct 任务时，先取得画布所有权及最新草稿，建立 `epoch / version` 下限，再订阅事件。时间线加载成功与否不能代替这个起点；最新草稿不可确认时保持只读并提供恢复入口，不从零播放旧检查点。
- 创建、继续、重试的响应丢失属于“结果未知”，保留只读并按原幂等键对账。GET 404 可能早于原 POST 提交，不能据此解锁；必要时重放同 key、同 payload。明确的首次请求拒绝或确认请求未发送，才允许 `preparation-aborted`；对账失败保留重试入口。页面恢复同样先取得画布所有权再恢复未知请求。
- 页面/账号会话结束使用 `detach` 取消本地回调，不把仍在运行的任务当作终态提交，不短暂解锁正在销毁的编辑器。
- 连续排队任务在父任务释放前确认子任务并交接画布。父任务最终 HTTP 快照可能包含子任务进度，因此交接后先读取子任务最新草稿，建立 `epoch / version` 起点再订阅 SSE，不能从旧检查点回放倒退。交接失败保持只读并可重试。
- 取消父任务后的异步收尾必须重新检查原任务 ID；若已交接到子任务，不得停止子任务的连接或终态轮询，即使子任务也已被服务端取消。
- 最终撤销历史以会话开始前捕获的正文为比较基线，而不是已播放完的显示树。AI 和播放期间的协作变化都属于远端变化；保留无关的人工撤销，清理有冲突的旧历史，不追加一条可撤销全部远端修改的“播放记录”。
- Preview 检查点是授权范围的投影，不是完整文档。恢复或“停止并保留”时，在服务端还原冻结整图上的授权变化，再生成结果或重新裁剪 Agent 输入；保留未修改的原始属性，不复活已删除节点，也不把范围外正文暴露给 Agent。
- Direct 条件撤销保留原始云端正文，规范化文档仅用于哈希校验，不能用其替换原始空白节点、富文本或视图。无法确认精确基线的旧回执、任务期间夹入协作者修改等情况，拒绝整图自动撤销，不猜测恢复内容。评论补偿统一按线程、评论的顺序加锁，并在锁内重读，保留协作者回复。

后端创建、继续、重试入口在业务拒绝后回滚，并按账号和幂等键检查是否存在已提交任务；确认不存在时才返回 `data.creationRejected:true`。技术错误、已存在任务或无法查证不返回该标记。它只证明本次请求被拒绝，不是该幂等键的永久取消凭证；复用持久化旧 key 或已进入未知恢复的请求不能据此解锁。

最终同步失败时保留画布、所有权和只读状态，并提供“重新同步云端结果”。不允许仅凭任务终态、超时或 `.finally()` 解锁。

## 结果统计

`changeSummaryVersion: 2` 表示本任务已提交操作的节点净变化，不是工具调用次数或 canonical 操作条数。

- 最终结果以任务自身的 `operationGroupId` 查询持久化操作，按提交顺序投影，仅回放 AI 实际改变的业务字段和结构差量；不拿当前整张云端正文与旧基线相减。嵌套对象、标签绑定按自身字段/标签身份处理，避免吸收快照中的其他协作者变化。
- 同一节点重复修改只计一次，改回原值为零；新增后删除为零，新增/删除节点不重复计入修改或移动。移动比较父节点和共同存活兄弟的相对顺序，不把新增、删除、跨父移动导致的被动下标位移算进去。同父重排可涉及多个节点，数量不是移动命令次数。
- 空操作不产生假提交，幂等重放不累计。评论和文档级元数据变更不冒充节点修改。各分类的合计允许同一已有节点同时属于“修改”和“移动”，不是全局唯一节点总数。
- Direct 的 proposal 是动态回执：ID 不变不代表统计已完成。成功、失败、取消的终态均重新加载；异步响应必须绑定任务与请求代次。展示优先较高统计版本，同版本使用完成事件覆盖早期回执，不对不同来源求和或取最大值。
- 旧任务可用自身 canonical 日志重算；日志缺失或前后证据不足时，保留完整的旧终态统计/兼容累计，版本保持 1，不把不完整重建标为精确净统计。新任务的版本 2 完成事件是持久化最终快照。
- 画布流式规划忽略 `isActive / inserting / needUpdate / resetRichText / activeStyle` 等临时字段；节点 UID 与兄弟顺序逐项比较，不使用分隔符拼接。

## 已有标签引用与建议

AI 不能创建或修改标签定义。三种 Agent 使用同一协议：先通过 `search_tags` 查询已有标签，节点写入仅接受 `[{"tagId": 7}]`；名称、样式、状态和定义版本由服务端解析。不存在或无权使用的身份不能回退为文本标签，也不能进入人工编辑使用的“按文本创建标签”兼容路径。

- 每轮重新读取可用标签目录，取“用户可见”和“当前文件可绑定”的交集，只检索启用标签；原节点已有停用标签可保留，不因此允许绑定到另一个节点。标签库检索独立于 `get_node_tags`，后者只读取授权节点已绑定的标签。
- 找不到合适标签时使用 `suggest_tags` 提供名称、原因和目标节点。建议通过独立 `tag_suggestions` 事件持久化并在当前轮/历史轮展示，明确标为“未创建、未绑定”；不写节点、不产生草稿游标、不计入节点变更，也不自动继续任务。用户手动创建后，在下一轮重新检索引用。
- 网关先解析真实标签身份，再计算净变更。正文操作和 `node.tag.bind / unbind / reorder` 分离；同批新增再改标签必须保留最终绑定，重复设置同一标签身份不制造修改计数或内容版本。
- Direct 写入后在同一事务中回读结构化正文。撤销哈希与按授权范围裁剪的流式检查点来自同一次实际回读，不把提交前候选树当作已保存内容；正文、检查点、回执和通知仍按同一事务提交。恢复中的 Direct worker 以最新云端正文重建授权草稿，不重新采用旧的未落库标签。
- 原有逐节点逐字播放不变。建议事件不参与节点聚焦或播放计划，修复标签一致性不引入整图替换入口。

## 回归验证

共用工具按职责集中，调用方不再保留同义实现：

- `ai/document.py::document_from_mindmap_detail` 统一云端详情到原始文档的字段映射；调用方仍负责权限、规范化和快照隔离，网关单独保留旧 envelope 的兼容规则。
- `ai/proposal_operations.py::_replay_proposal_operations_in_place` 统一冻结操作的校验与回放；规范 Proposal 和编辑器原文入口各自创建私有副本、验证结果，不能以规范文档覆盖未改动的富文本和视图。
- `ai/adapters/base.py` 统一 Native/Claude 草稿事件与工具完成回执、Claude/Codex 结构预算提示；取消检查、事件发送和各 provider 的错误恢复仍在适配器中。
- `mindmap-ai-errors.js` 统一取消错误识别；`mindmap-ai-shared.js` 统一数字账号身份校验/归一化及 SHA-256 字节摘要。存储记录严格校验与用户输入归一化仍使用不同入口；摘要前的规范化与环境错误提示仍由调用方处理。
- 新建、重试、排队续写与完成后续写共用运行策略校验和任务配置组装；排队任务仍不占用执行并发名额。DAO 单条查询共用执行器，各查询的权限条件仍显式定义，锁定读取保留 `FOR UPDATE / populate_existing`。

清理边界：播放规划器只有逐节点、逐字模式，不再提供未接入的批量/全文直出开关。Dialog 不发送编辑器无人消费的 `status` 通知，也不传递旧渐显字段；有效的开始、更新、排空、提交、清理和会话所有权仍保留。云端草稿通过版本化快照获取，浏览器不维护第二套本地 delta 重建入口。未接入的居中辅助函数不作为实际聚焦行为的测试替代，实际行为由 Editor 与渲染器回归覆盖。

重试与继续调整由统一输入框提供，不再保留被 CSS 永久隐藏的旧面板和专属样式。Proposal 移动/删除复用当次树索引，移动位置仍按移除后的子列表校验；本地日志阶段列表从唯一的迁移表派生，合法、幂等、非法迁移及失败不写存储均有行为回归。

后端统一使用带统计版本的真实结果入口，已删除旧操作次数统计器和仅测试调用的包装函数。完整证据只计算一次任务净变化，只有缺少完整证据且没有最终回执时才计算兼容备用统计；Direct 与 Artifact 预览的终态分支保持分离。

直写网关逐条校验并更新候选树，仅记录受影响的节点身份和结构父节点，批次结束后统一生成净变更；不再构造随后丢弃的中间 canonical 操作和父节点快照。结构差量按最终树的父先子后顺序先回放，再写节点正文、标签和删除，避免新增节点的最终下标与旧兄弟下标碰撞。权限、CAS、幂等、事务回读和广播边界仍由原有领域服务执行。

- `npm run test:mindmap`：包括规划器、节奏、实际 Dialog 生命周期函数、Editor 会话所有权、协作与保存恢复行为测试。
- 启动 Vite 后执行 `node scripts/test-ai-stream-browser.mjs`。默认使用独立 Chrome 配置与 `http://127.0.0.1:5173`；可用 `CHROME_BIN`、`VITE_TEST_URL` 调整。
- 后端：`.venv/bin/python -m pytest -q tests/test_mindmap_ai_creation_receipt.py tests/test_mindmap_ai_boundaries.py tests/test_mindmap_ai_realtime.py tests/test_mindmap_ai_recovery.py`，覆盖拒绝回执、已提交结果保护、实时通知和恢复边界。
- 后端单测默认禁止真实数据库建连，即使业务代码捕获了连接异常，也会判定测试隔离失败；显式数据库集成测试仍通过 `MINDMAP_DB_INTEGRATION=1` 启用。调度、DAO 和会话边界必须在对应测试中替换并验证调用，不能静默访问开发库。
- 统计：`tests/test_mindmap_ai_change_summary.py`、`tests/test_mindmap_ai_mutation_gateway.py`、前端 `mindmap-ai-result-summary.test.mjs` / `mindmap-ai-dialog-lifecycle.test.mjs`，覆盖首批 8 → 最终 84、重复/撤回/重放、失败取消、旧回执、协作间隙与跨批随机结构变化。
- 网关：固定种子的混合新增、修改、移动、删除、标签和布局操作，使用独立小树模型比对真实领域回放结果、兄弟顺序与回读哈希。
- 标签：`tests/test_mindmap_ai_tag_projection.py` 使用真实网关、batch 合并、持久化解析和 DAO 回读，仅替换数据库 I/O；`tests/test_mindmap_ai_tag_recovery.py` 覆盖目录权限、每轮刷新、权威检查点与建议事件；前端 `mindmap-ai-tag-suggestions.test.mjs` 覆盖任务隔离、历史重放、纯文本展示和不触发画布修改。
