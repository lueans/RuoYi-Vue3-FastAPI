## 本轮边界修复与剩余风险（2026-09-26）

- 工作台体验审查后的补充：任务等待器现在把 `ready` / `needs_review` 等全部终态视为执行栅栏，并检查当前执行 epoch。HTTP 在另一 worker 上保留草稿，或新 worker 已接管任务时，旧 Adapter 不再仅因状态不是 `cancelled` 就继续运行；迟到结果仍经原 SDK 会话丢弃回调清理。

### 结果状态与执行停止回执分离（2026-09-26）

HTTP 取消仍可先持久化 `cancelled`，或将保留草稿提升为 `ready` / `needs_review`，以关闭本轮写入并保留已生成的内容；这些结果状态不再作为退出证据。任务快照独立返回 `executionState`、`executionEpoch` 和 `cancelRequestedTime`：

- 由拥有当前执行 epoch 的任务管理器写入 `execution_state` 事件，状态为 `running`、`stopped` 或 `unconfirmed`。供应商输出不能自行发布退出回执。新任务尚未认领时为 `not_started`；旧执行缺少证据时为 `unknown`，不根据 `ready` 或 `cancelled` 猜测停止。
- ORM 从现有事件表投影最新回执，不增加数据库列或迁移。开始执行还需当前租约；旧 epoch 回执不能覆盖新执行，同一 epoch 的有效 `stopped` 不被迟到的失败覆盖。服务端重试、追问和排队接力在未确认停止时拒绝启动下一轮。
- 前端停止查询独立于结果/草稿的终态加载：保存结果后仍可有界轮询，确认后解除发送、重试、切换 Agent 和切换会话的限制；超时/未知状态提供手动刷新，不自动重试模型调用。切换只选择下一轮 Agent，不自动发送。
- 账号、任务、执行 epoch 变化或组件销毁使旧查询失效；其他任务的响应、旧 epoch 快照和畸形回执不能解除限制。按独立 watch source 比较身份，避免每次快照更新触发无间隔请求循环。
- 租约接管发现旧执行仍在运行或未确认时，不启动替代执行：记录失败与未确认状态、清理旧检查点并发布终态通知。清理超时后的实际迟到退出可补充回执；二次取消不能掩盖已经完成的清理失败。

这轮修复了真实 DAO 落库时重复传入更新时间导致回执事务回滚的问题。隔离 SQLite 使用生产 DAO SQL，覆盖回执投影、同会话刷新、epoch 栅栏、租约恢复、正常取消与保留草稿取消、重复请求及迟到退出；保留草稿测试仅替换加密草稿提升步骤，不宣称验证了真实供应商全链路。

验证：后端脑图全量 **1895 项通过、23 项跳过、148 项子测试通过**；显式启用隔离 SQL 测试 `MINDMAP_DB_INTEGRATION=1 .venv/bin/python -m pytest tests/test_mindmap_execution_evidence.py -q` 为 **21 项通过**；前端 **1388 项通过**，生产构建通过。自动化测试不连接业务数据库；页面验证只读取既有脑图并操作面板，未执行迁移、调用真实模型或修改业务脑图。

实际页面检查另发现并修复窄屏命令弹层的层叠问题：页头外部的遮罩盖住了页头内部的命令面板，点击 AI 按钮实际关闭弹层。现将遮罩与面板置于同一页头层叠上下文；新增模板结构回归，且在 380px 页面核验按钮命中、AI 面板打开及配置入口，临时尺寸和测试标签页已恢复/关闭。该验证不代表运行中停止提示已通过真实模型端到端验收。

**仍有边界：**缺少回执的旧取消任务和服务崩溃后的遗留执行可能停留在 `unknown` / `unconfirmed`；刷新不是人工豁免，也不会伪造已停止。本机桥接已增加下文的磁盘登记/启动前回收，但不向服务端旧任务补造停止回执；平台主机崩溃回收和有审计的人工恢复流程尚未实现。当前回执证明的是对应 Adapter/设备执行合同已结束，不扩大各驱动原有的进程清理能力。未改变直接编辑/云端保存策略、实时 `draft_changed` 预览和采纳/撤销语义。

## 两条流保持分离

### 浏览器连接静默与续播（2026-09-26）

参考 OpenDesign `apps/web/src/providers/daemon.ts` 的读超时与重连退避，在原有任务监控中补齐“代理保留 HTTP 连接但不再转发 SSE”的恢复路径：

- 服务端空闲时约每 15 秒发送 keepalive；前端将响应头、错误响应体和逐次流读取的等待限制为 45 秒。任何实际网络分片（包含 keepalive）使下一次读取重新计时，不限制 Agent 总运行时长，也不把本地事件处理耗时算成网络超时。
- 超时仅取消本次 SSE GET 的独立 AbortController，保留任务、外层监控和独立的版本化草稿请求。底层 reader 的取消确认即使不返回，也不阻塞重连；定时器和外部 signal 监听在退出时清理。
- 浏览器原生 reader 的 `AbortError` 不能覆盖超时原因，否则监控会将它误当成人工关闭而跳过重连。调用方主动中止仍保留原中止原因，不再请求后续事件。
- 仅响应头、空 EOF、重复序号或解析错误不重置重连退避；收到新序号的有效事件才重置。既有有界指数退避、轮询和任务/连接代次校验保留，断线只携带原任务 `Last-Event-ID` 续读，不重新创建或运行模型任务。

验证新增 12 项回归，前端全量 1518 项通过、生产构建通过。测试包含原生 fetch + 实际回环 HTTP 服务：静默连接触发可重试超时且旧 socket 关闭；中途断开后同任务续播、重复事件去重，两版草稿均送达，全部请求为 GET。45 秒超时由测试时钟推进，不实际等待；调用方中止、永久挂起的清理、迟到数据、正常心跳、生产重连函数的退避/旧连接失效也有回归。测试服务只绑定随机回环端口，不接触业务数据库、真实 Agent、登录凭据或付费模型；不将其等同于实际部署代理、浏览器后台节流和真实 Agent 的端到端验收。

### 聊天与脑图通道

```text
Native Agno / Claude SDK / Codex app-server / Kimi ACP
  ├─ 可见文本、思考状态/摘要、工具详情、Todo
  │    → RuntimeTrace → 原有 JobEvent 存储 / SSE → AgentTrace
  └─ mindmap MCP 工具
       → 原有 MindmapToolService → draft_changed
       → 原有执行 epoch、检查点、云端提交、画布流式播放
```

新增对话事件不会执行脑图变更。停止与切换仍经过原有取消接口、终态检查点排空和队列交接；不直接杀掉界面连接后假装已经停止。切换确认后仅改变下一次发送的 Agent，不自动提交额外一轮请求，不将上一家的私有会话 ID 交给另一家。

## 已接入能力

- 普通 AI 使用权限即可打开“管理 Agents”、扫描运行主机上的已知 CLI、设置个人默认 Agent，以及开关个人使用列表。
- 个人设置保存在当前浏览器、当前账号的 localStorage。不会修改全局 Connector，不提供跨设备偏好同步。
- 扫描 `PATH`、`~/.local/bin`、`~/.npm-global/bin`、Homebrew 常用目录。版本/帮助探测有超时和输出上限，不调用模型、不自动安装或登录。
- Codex 通过官方 SDK 驱动已发现的本机 CLI；没有独立 CLI 时使用 SDK 内置版本。
- Claude 使用官方 SDK 的部分消息流；本机 CLI 必须支持当前会话镜像合同才会被选用，否则使用 SDK 内置 CLI 保留续接兼容性。管理页分别标注扫描版本和实际执行来源。
- 对话正文、供应商公开的思考摘要、工具调用参数/有界结果/耗时、真实任务计划可实时查看及历史回放。隐藏推理只映射成状态，不显示内部思维链。
- 新增平台 `update_plan` 工具，不改变脑图。Todo 不由界面伪造；Agent 没发布计划时不显示计划。
- 讨论模式的结构化输出只增量提取公开的 `content` 字段，不向 UI 输出整个 JSON。

### Native 编辑执行过程

默认 MindMap Agent 的 Agno 编辑流也进入同一时间线：公开文本增量、工具调用 ID、经过校验的参数、有界结果、耗时和实际 `update_plan` 计划。工具边界会先排空正文缓冲，避免进度文本落在对应工具之后；最终聚合消息不重复显示。非法工具参数不回显，隐藏 `reasoning_content` 只产生“思考中”状态。

Native 的工具详情只在工具成功通过领域校验后披露参数，失败事件保留脱敏原因和关联 ID。并发工具仍经过原有串行变更边界；Todo 不产生 `draft_changed`，不能绕过 `validate_draft` / `complete_artifact`。取消后不追加正文；事件持久化失败后不允许 SDK 继续伪装执行。Native Adapter / Prompt 版本更新为 `1.13.0` / `mindmap-agent-13`。

注意：Native **讨论模式**仍使用非流式结构化结果，避免当前 Agno/Ollama 流式接口丢失 `response_format` 合同；不伪造逐字流。上述 Native 实时过程对应有工具的编辑模式。

### 跨 Agent 的编辑上下文接力

沿用 OpenDesign `runtimes/types.ts` 区分的两条路径：已有供应商会话的同 Agent 续接不再重复注入历史；切换 Agent、Native 等无持久会话的编辑续接，由平台补充最近最多 4 个可信内容/重试来源轮次的用户要求，每条最多 3000 字符。2026-09-26 另按 `agent-session-resume.ts` 的“无法恢复供应商会话时必须补充可见历史”原则，加入这些祖先中已完成讨论的实际答复，支持“按第 3 条建议修改”等指代。当前授权投影仍由原有工具层提供，历史不是修改权限，也不是脑图已保存/应用的证明。

- 创建续接时，服务端记录 `contextParentJobId`，指向用户实际选择的 Artifact 所属任务，而不是盲目使用最近聊天任务。队列释放时记录实际提供内容的父任务。
- 失败任务重试保留这条内容来源标记，但仍创建全新的供应商会话；执行时重新校验内容祖先的权限、来源范围与保留期。重试另优先沿服务端任务行的 `retry_of_job_id` 读取来源轮次的要求，避免“继续未完成部分”覆盖原要求后失去指代。仅可信重试关系可带入 failed/cancelled/stale/expired 终态；客户端请求中的同名字段不授予读取权，已过保留期、仍运行、不同会话或范围的轮次不读取。
- 每个祖先都校验用户、会话、终态、保留期和来源/范围；跨文档、跨房间 epoch、授权范围变化即停止读取。只读取最多 4 个任务，不加载整个会话日志。
- 携带前序用户要求、Agent/意图/任务状态、经过身份核验的可见讨论答复和有界计划快照；不转移供应商会话 ID、工具原始输出、隐藏推理、凭据或完整运行日志。历史 JSON 明确标为不可信，不能覆盖本轮要求。
- 讨论答复通过绑定的 `response_id` 和当前用户读取，再核验答复 ID、所属任务、用户和保留期。不存在、过期、空正文或绑定不匹配时，上下文装配以 `AI_SESSION_UNAVAILABLE` 失败，不能在缺少建议正文时直接开始编辑；没有跨范围回捞全文。
- 每条讨论答复最多 20000 字符，总答复预算 40000 字符，最新建议优先，最终仍按时间顺序传递。正文继续脱敏和转义历史分隔符；截断显式标记 `assistantReplyState=truncated`，提示 Agent 不得猜测未提供的建议，指代不清时先请求补充。
- 编辑来源轮次只读取最新一条 `todo_updated`，同时按任务、用户和保留期查询。只接受 `origin=agent` 的可见计划；空列表表示明确清空，不退回旧快照。每项最多 500 字符，全部上下文合计最多 40 项、最新优先，已知条目省略标记 `agentPlanState=truncated`。与聊天展示一样，计划本身已是有界投影，不宣称包含供应商全部内部任务。
- 计划只传正文与 `reportedStatus`，不复用旧 Todo ID、不当作新 Agent 的当前任务或完成事实。提示词要求先核对当前授权脑图再建立新计划；旧 in_progress 不代表仍有进程运行，completed 也不证明当前文档仍有该结果。缺失、清空或截断时不能猜测或自动重跑。
- 这是“目标上下文接力”，不是跨厂商复制完整 SDK 记忆。没有内容来源标记或服务端重试关系的旧任务不会被猜测补全；助手执行过程仍留在原聊天历史，不整段重新注入。

讨论转编辑的回归贯穿实际续聊创建（包含 `contextParentJobId`）、内容祖先读取、Claude/Codex/Native 提示词、Kimi ACP prompt，以及本机 Claude/Codex/Kimi 的实际 `run` 载荷。测试使用模拟模型/DAO 与真实协议装配，不发起付费请求、不改写业务脑图。真实账号运行中的停止时延、断线恢复和跨 Agent 完整接续仍需独立验收。

计划/重试补充验证：后端脑图全量 1946 项通过、26 项显式 opt-in 用例跳过、148 项子测试通过（20 条既有 WebSocket 依赖弃用警告）；另显式启用隔离 SQLite 的执行回执回归 22 项通过。实际 DAO SQL → 上下文装配 → 提示词验证了最新计划清空、用户隔离和过期；实际 `retry_job` 创建 → 可信来源 → Claude 提示词验证了换 Agent 后保留原要求、使用最新云端内容且不恢复失败会话，房间 epoch 变化时不注入旧上下文。未迁移/访问业务数据库、重启服务、配对设备或调用真实模型；实时脑图草稿、写入/撤销和停止确认协议均未修改。

## Kimi ACP（实验性、显式启用）

平台 Kimi 使用 `kimi acp`，顺序为 `initialize → session/new → session/prompt`，中断发送 `session/cancel` 后终止本轮进程。脑图工具通过每轮独立的、仅监听 loopback 的 HTTP MCP 服务提供。OpenDesign 的 stdio MCP 兼容性注释针对当时核验的 0.37.0–0.38.0，不应推广为“所有新版 Kimi 都不支持 stdio”。当前 [Kimi Code ACP 文档](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-acp) 已列出 stdio 转发；Python `kimi-cli` 仓库也已声明归档并迁移至 [Kimi Code](https://github.com/MoonshotAI/kimi-code)。新版设备执行采用独立审核的 2.1.1 受限驱动，见下文；不能把本节实验性平台 Adapter 的边界与设备驱动混用。

与 Claude/Codex 受限 SDK 不同，Kimi 仍拥有 CLI 自身的工具和本地配置；ACP 客户端不开放文件/终端能力，并且不批准其他工具权限，但这不等于 OS 沙箱。必须由部署者为其准备独立、最小权限运行账号后启用，不能共用持有数据库等应用凭据的服务账号。默认 `MINDMAP_AI_KIMI_ENABLED=false`，本次未修改运行环境或执行数据库迁移。

启用步骤：在运行主机安装并登录 Kimi；先确认已执行 `20260910_mindmap_ai_agent.sql` 对应数据库版本，再执行合并迁移 `20260926_mindmap_agent_runtime.sql` 或 `20260926_mindmap_agent_runtime_postgresql.sql`；设置 `MINDMAP_AI_KIMI_ENABLED=true` 后重启服务，再在 UI 重新扫描。合并迁移也包含设备表和三个默认停用的设备 Connector；平台 Kimi 保留原默认启用值，重跑不会覆盖现有管理员 Connector 策略。

当前 Kimi 限制：使用 CLI 当前默认模型；不切换主机全局模型、不宣称原生会话续接、不支持零工具讨论、不报告未提供的金额/Token 用量，也不声称具备供应商金额硬限额。以任务超时和工具调用次数控制执行。接口与 HTTP MCP 已做协议级测试；本机没有 Kimi CLI，未做真实模型调用验收。

Kimi 官方实现核对：[ACP 服务端](https://github.com/MoonshotAI/kimi-cli/blob/main/src/kimi_cli/acp/server.py)、[CLI 文档](https://moonshotai.github.io/kimi-cli/en/reference/kimi-command.html)。新 `kimi acp` 不应套用旧 `--acp --agent-file` 启动方式。

### ACP 实时记录补充（2026-09-26）

- 对照 OpenDesign 的 `agent-protocol/acp/session.ts`，按调用 ID 保存有界状态，合并部分参数和结果；首帧立即上屏，重复帧去重，变化中的帧限频，终态不受限频。状态单独返回时仍保留前面的工具名称和详情。原始调用 ID 仅留在进程内，输出使用本轮不透明 ID，避免路径/令牌进入记录标识。
- 已由权威脑图 MCP 网关记录的调用按本轮允许的精确命名空间去重，后续无名称帧仍不重复显示。其他 CLI 工具不会仅因名称包含 `mindmap` 就被隐藏；已识别的思考类工具只回显状态，不回显推理内容。
- 不复制“回复结束即合成工具成功”的做法。未收到工具终态时保留未确认状态；只有孤立完成帧时不编造开始时间、耗时或 Todo 归属。前端同一调用的名称/参数更新保留原位置和步骤，迟到的开始帧不能覆盖已完成结果。
- 权限检查绑定当前 session、正在进行的 prompt、已收到的工具开始帧、本轮工具集合及精确 MCP 命名空间，只允许一次授权；不采用裸名称/任意后缀匹配，也不允许 `allow_always`。这些是可信 CLI 协议的收敛检查，不是 OS 沙箱，不能阻止 CLI 自身绕过批准执行原生工具，独立运行账号要求不变。
- 取消或收到 prompt 响应后立即关闭实时发布和批准入口。重复/畸形 RPC 响应、重复反向请求 ID、布尔 ID、非法 JSON 数值均失败关闭；读流结束后新请求立即失败，写入 stdin 的背压也计入请求超时。

该平台 ACP 补充不更改 `draft_changed`、草稿校验、确认应用或原画布逻辑。设备端扫描与执行另行授权，设备 2.1.1 驱动的版本、登录隔离和工具策略见下文；不能把扫描成功宣传为已认证或可安全执行。

隔离验证使用临时 Python ACP 对端与真实 HTTP MCP/脑图工具网关：6 次授权工具调用各保留一组开始/完成记录，重复 ACP 完成帧不增加卡片，2 次 `draft_changed` 和 2 次 Todo 更新保留。正文/详情经过聊天字段收敛；草稿操作按独立预览通道检查，未塞入聊天字段白名单。该测试不使用 Kimi CLI 或真实模型，不访问应用数据库，也未修改任何业务脑图。

## 执行进程的停止确认

参考 OpenDesign `runtimes/agent-process.ts` 的“进程组仍有成员就不能认为已退出”规则，修复原来只检查 `process.returncode` / 等待父进程的清理逻辑。

- `spawn_owned_process` 记录本进程实际创建的独立进程组及 CLI 父进程创建时间。启动过程中被取消，也要等到取得真实进程句柄并清理后才返回。
- `terminate_process` 等待整组仍可运行的成员退出；父进程先退出、子进程忽略 SIGTERM 时仍升级 SIGKILL。并发清理复用同一个任务，重复取消不会中断清理；已完成的句柄不重复按旧 PID 发信号。
- 创建时间表明 PID 已被其他进程复用时不发送进程组信号；没有本次创建记录的普通对象不授予进程组终止权。无法确认清理完成时返回 `AI_AGENT_CLEANUP_FAILED`，不得透明重试或接受成功结果。任务取消的有界等待也会传播这个失败，前端提示先检查运行主机。
- 已接入：Codex 隔离 worker（包括成功返回后的残留子进程）、Kimi ACP、平台 CLI 扫描、Claude 认证探测。Claude 主执行进程仍由官方 SDK 管理，不能把这里的覆盖范围误称为所有 SDK 内部进程。
- CLI 扫描失败会取消并等待同次扫描的其他探测，不留后台探测任务。Claude 能力使用 `-p --help`，与 OpenDesign 的 print 模式探测一致；版本输出只提取有界版本号，不回显任意诊断文本。

验证使用真实的临时 Python 父子进程与模拟 worker，不调用供应商模型：`tests/test_mindmap_owned_process.py` 覆盖父进程先退出、忽略终止信号、并发/重复取消、启动竞态、PID 复用、成功返回后的残留、清理失败不重试及取消失败传播。

本节平台主机实现是 **运行中进程所有权与清理**，尚未实现 OpenDesign 的磁盘进程记录和服务崩溃后的启动回收，也不约束主动脱离进程组的任意程序。独立本机桥接另有下文的持久登记/启动前恢复。POSIX 组清理已验证；Windows 仍只有直接子进程清理，不宣称具备完整 Windows 进程树隔离。本机 Claude 的执行授权、任务分发、MCP 回传和取消确认已由下文独立接线；本节的进程测试本身不代表完整用户流程已完成。

## 用户电脑上的 CLI 发现（独立、可选的桥接）

新增 `mindmap-agent-bridge` 独立 Python 伴随程序，以及用户设备配对、扫描、撤销 API / WebSocket 通道。网页“管理 Agents”明确分为“平台运行主机”和“我的电脑”。后者显示设备在线状态、扫描结果、登录状态未检查和临时配对码；关闭或切换账号会清除配对码，并使旧异步响应失效。普通用户不再被引导把服务端扫描误认为浏览器电脑扫描。

普通 `run` 和扫描通道仍然是 **发现模式**：仅允许 Claude/Codex/Kimi 公开版本和限定能力上报，不读取脑图、不调用模型、不开放任意命令/路径输入、不上传 CLI 凭据。另有默认关闭、必须在本机显式启用的 Claude / Codex / Kimi 执行通道，见下文；Codex、Kimi 另需各自预算限制的明确同意。现有服务器 Agent、MCP 工具和 `draft_changed` 流式预览链路不受影响。

- 5 分钟配对码、90 天设备授权、哈希存储、用户归属校验；客户端先持久化随机密钥再配对，以便安全重试丢失响应。
- 主动建立出站 WebSocket，无本地监听端口；拒绝浏览器 Origin、URL 中的凭据和连接重定向。
- 每帧重新校验授权及账号状态；新连接隔离旧连接；扫描序号合并重复请求，旧结果不覆盖新结果。有效设备优先于历史过期记录，保证用户始终能撤销有效授权。
- 有界版本/帮助探测、进程组回收、输入输出白名单；兼容项目现有传输加密，失败不降级。

### 设备执行协议（独立于扫描通道）

在扫描通道之外，`device_run_session.py` / `device_run_transport.py` 和伴随程序的 `execution.py` 实现单轮执行协议，已通过下文的调度接线进入独立执行 WS 和真实任务管理器。普通 `run`、已有配对和扫描协议仍不授予执行权限；必须同时满足管理员开关、Connector 策略、本机显式启用和本人任务/文档授权。

协议采用 OpenDesign 的“进程驱动与领域工具分离”方式，保留本项目的权威任务及草稿工具层：

```text
可信本机驱动 → 序号化 tool_call / public_text / thinking / heartbeat
  → DeviceRunSession（任务/设备/执行版本绑定 + 每帧授权回调）
  → 原有脑图工具网关 → 工具详情 / Todo / draft_changed → 原有事件存储入口
平台 cancel → 立即拒收新操作 → 本机驱动 stop → stopped 确认
```

- 执行身份由服务端构造，不从设备消息恢复；每帧绑定 `runId` 和 `executionEpoch`，严格拒绝未知字段、乱序、伪造草稿和非白名单工具。同一帧只允许精确重放最后一次响应，不重复调用工具；不自动重连或重试执行。
- Agent 选择必须匹配本机预先选定项，并由必填的本机同意回调明确返回 `True` 后才启动驱动。远端消息不能提供可执行文件、参数、目录、环境或凭据。Claude/Codex/Kimi 各有独立驱动；Kimi 使用版本 3 执行握手并明确接受无金额预算上限，不影响现有服务器端 Adapter。
- 提示词与工具描述单独构造，不序列化包含平台凭据的 `context.metadata`。设备只能发送已归一化的公开正文/思考摘要；不接受原始 SDK envelope、隐藏推理字段或自称完成的脑图文件。正式驱动必须在发出消息之前完成公开事件提取与脱敏。
- 工具仍调用真实 `MindmapToolService`。预览完成必须经过 `complete_artifact`；直接编辑必须校验最后一次修改；已经创建/修改草稿不能转成补充问题终态。Todo 不修改脑图，讨论不暴露工具。
- 取消有独立读循环，能打断正在等工具响应的本机驱动。终态必须确认进程已停止；清理失败发送 `processStopped=false`，平台保留 `AI_AGENT_CLEANUP_FAILED`，不伪装成取消成功。已完成并校验的服务端结果不因最后 ACK 丢失变成失败重试。
- Python 3.10 的 `wait_for` 在“子操作刚结束与外层取消同轮到达”时可能吞掉取消；执行通道使用保留取消的有界等待，并用确定性竞态测试覆盖。重复取消不跳过清理。
- 输入单帧 2 MiB、工具响应 8 MiB、每轮最多 2048 帧、公开过程最多 100000 字符；协议终态不携带未经校验的原始异常信息。不在应用代码记录原始消息。

Claude / Codex / Kimi 的跨 worker 分发、任务/设备/租约授权、原事件存储入口、显式执行开关、网页设备选择器与进程退出验证已经接线，详见下文。真实账号部署验收尚未完成；本机启动前恢复只处理可验证的旧资源，不替代服务端旧任务的停止回执。配对凭据不能代替文档授权，部署时也必须关闭 WebSocket 的 debug frame 日志，不能记录真实任务正文或 Authorization。

`tests/test_mindmap_device_run.py` 使用真实回环 WebSocket、原有工具网关和模拟本机驱动，验证正文、Todo、实时草稿、终态、中断和权限失效；`mindmap-agent-bridge/tests/test_execution.py` 验证本机明确同意、受限协议、迟到 ACK、重复取消和清理失败。测试不访问应用数据库、不调用模型，不代表真实 CLI 端到端验收。

### Claude 设备端驱动（已接 CLI、任务 API 与网页选择器）

`ClaudeRunDriver` 在独占进程组中运行 `claude_worker.py`，worker 使用已验证的 `claude-agent-sdk==0.2.152` 驱动本机扫描到的 Claude CLI。SDK 实现 stdin `stream-json` 与 MCP 控制协议；不解析终端展示文本。实现方式参考 OpenDesign `runtimes/defs/claude.ts`、`claude-stream.ts` 的公开事件拆分，同时保留本项目受限工具策略。SDK 的本机 `cli_path`、内存 MCP 和查询接口见 [官方 SDK](https://github.com/anthropics/claude-agent-sdk-python/blob/main/README.md)；流式和工具参数见 [官方 CLI 参考](https://code.claude.com/docs/en/cli-reference)。

- 安装依赖是独立的 `mindmap-agent-bridge[claude]` 可选项；没有自动安装、登录或调用模型。驱动拒绝未验证的 SDK 版本，发现功能不依赖此可选项。
- worker 的系统环境采用本机白名单。Claude 常规登录仍由 CLI 在本机处理；支持本机终端的 Anthropic Key/Auth Token/OAuth Token/Base URL，不把数据库凭据、Python/Node 加载注入变量或远端环境参数交给 worker。不会读取或上传 CLI 凭据文件。自定义用户 settings 中的认证扩展及 Bedrock 等其他认证方式尚未接入此设备驱动。
- `tools=[]` 禁用内置执行工具；`strict_mcp_config` 只载入本轮内存脑图 MCP；只预授权具体的脑图工具名，其他工具不允许弹出后自动批准。不复制 OpenDesign 的 `bypassPermissions`。
- 禁用自动加载用户/项目 settings、skills、plugins、agents、slash commands 和普通 hooks；使用每轮私有工作目录和 `--no-session-persistence`，不把旧厂商会话混入新一轮。目录内有最小所有权记录，正常清理与崩溃后回收见下文。受管理策略和 CLI 自身行为仍可能影响运行，这不是 OS 沙箱，不绕过组织策略。
- Claude 正文在设备端归一化、去重、分片脱敏后才上传，工具/Todo 来自平台网关。当前 Claude 驱动只把隐藏 thinking 映射为状态，不将其标成公开摘要；没有伪造缺失的供应商思考内容、用量或费用。
- 完成结果先在设备校验公开字段和长度，再由平台校验真实工具完成契约。401/403、429 映射为固定公开错误码，原始 stderr、初始化信息、供应商 session ID、隐藏推理和诊断内容不进入设备事件。
- `OwnedProcess` 记录实际创建的 worker 进程组与创建时间。SDK 的 CLI 子进程留在同组；正常完成和中断都验证整组退出，必要时升级 SIGKILL。父进程已退出但仍有子进程、重复停止、spawn 过程中被取消、PID 被复用都单独测试。不能确认停止时不删除本轮工作目录、不接受成功结果。

新增测试用 `tests/fixtures/claude_mock.py` 作为临时可执行 CLI，走**真实 SDK 初始化、MCP JSON-RPC、独立 worker、设备 WebSocket 与平台工具网关**。模拟的是供应商 CLI/模型响应，不是 SDK、传输或脑图编辑器；测试覆盖创建、Todo、流式节点、中断、忽略 SIGTERM 的残留进程、认证失败、限流和工具错误。未调用真正的 Claude 模型，未验证真实账号/服务商可用性；网页选择与请求参数已接入，但尚未进行部署后从网页到真实设备/模型的全链路验收。

### 设备任务调度与出站执行接线（默认关闭）

新增 `device_claude` / `device_codex` Adapter，作为和服务器 Agent 不同的执行位置。创建、重试和追问使用 `deviceId`，该值进入原任务请求快照和幂等摘要；任务详情回传设备 ID。切换到服务器 Agent 清除旧设备参数，切入本机必须选择设备。同 Agent 追问沿用父任务的设备，选择旧 Artifact 只选择内容，不会偷偷切回旧电脑。

```text
任务 API（本人 deviceId）→ 原 Connector/并发策略 → 原 Job worker / 执行租约
  → Redis 原子预留设备与所选 Agent → 独立出站执行 WS → 本机 Claude SDK / Codex app-server
  ← 公开正文 / 工具请求 / Todo → 原工具网关 → 原 _emit / SSE / draft_changed
取消 → 立即拒收新操作 → CLI 进程组退出 → 停止回执 → 原任务终态
```

- 扫描与执行开关都默认为 false；两个设备 Connector 迁移均默认停用。普通 `run` 不执行任务；只有本机显式 `--execute` 才建立执行连接。Codex 另需 `MINDMAP_AI_DEVICE_CODEX_ENABLED` 和本机 `--accept-estimated-budget`，见下文。配置文件或远端 welcome 无法启用本机执行。
- 每个设备一个原子连接槽、每连接一轮任务，连接 TTL 20 秒。队列按设备 hash tag 分区，每方向最多 8 条、合计 16 MiB、30 秒 TTL；过期/替换连接不能读取、发送或清理新连接的数据。不依赖 Web worker 与任务 worker 位于同一个进程。
- WS 使用设备 Bearer header，拒绝 Browser Origin 和任意 Agent；SQL 逐帧校验设备凭据、有效期及账号，发送任务/工具结果之前再次认证与核对连接。任务 worker 每帧核对本人设备、job/session、执行 epoch、活动租约和源文档读取权限；编辑仍由原工具层检查并持久化。
- 仅白名单运行参数 `modelRef` / `maxBudgetUsd` / `timeoutSeconds` 下发，Claude SDK 获得同一冻结模型和金额预算，客户端也执行时间上限。平台密钥、SDK session、路径、argv、env、租约 token 不下发；金额约束不宣称独立计费/对账保证。
- 不使用通用 Adapter 的透明重试；worker 重启认领旧执行 epoch 时拒绝重新启动 CLI，提示人工确认旧 CLI 已停止后再明确重试。连接断开也不重播任务。已验证结果和原脑图预览保存逻辑不另起一套。
- 中断流程等待本机停止回执；权限撤销导致连接断开时，即使本机自行清理，平台没有回执也显示 `AI_AGENT_CLEANUP_FAILED`，而不是声称已确认取消。正常完成只允许停止后的结果；最终 ACK 丢失不丢弃已经验证的服务端结果。

`tests/test_mindmap_device_dispatch.py` 自行启动独立 Unix Socket Redis，使用实际 ASGI/WebSocket 路由、跨连接分发、原工具网关，以及真实 SDK + 临时模拟 CLI。SQL 任务/权限依赖在此测试中隔离替换；设备表 SQL 行为另由显式 SQLite 测试覆盖。新增断线、撤销、租约失效、并发抢占、旧连接清理、队列上限、设备切换、任务管理器接入与禁用透明重试测试。它们不连接应用 Redis/数据库，不访问付费模型，不能替代部署后的真实账号验收。

### Codex 设备协议内核（已接线，默认关闭）

`mindmap-agent-bridge/mindmap_agent_bridge/codex_session.py` 参考 OpenDesign 的 `apps/daemon/src/agent-protocol/codex-app-server/session.ts` / `normalize.ts`，实现单轮 `initialize → initialized → thread/start → turn/start → turn/completed`；采用 [官方 Codex App Server 协议](https://learn.chatgpt.com/docs/app-server)。不是从终端文本抓取伪流式输出。

- 动态工具统一以 `mindmap_` 前缀注册，避免与内置计划工具重名；`item/tool/call` 只接受当前线程、当前轮次、已授予名称和对象参数。结果经原设备 `RunChannel.tool` 回传，计划及编辑工具仍应由平台网关产生权威事件和实时草稿。
- 请求 ID / 调用 ID 去重，拒绝越界工具、权限请求及已知的文件/命令/MCP 执行项；前置事件有界缓冲，兼容事件早于 `turn/start` 回复的次序。不恢复、重跑或复用已结束会话。
- `codex_trace.py` 只映射公开正文与明确的 `summaryTextDelta` / `summary`；原始 reasoning 仅转为思考状态。供应商线程/轮次/消息 ID 不上传，文本增量与完整消息去重，分片凭据先脱敏再进入设备事件。最终结构化结果不冒充聊天正文。
- 公开文本处理与最终结果 schema 提取为 `public_trace.py`、`completion.py`，Claude 驱动复用同一规则，已有 Claude 回归测试保留。
- `turn/interrupt` 仅表示已请求停止，不作为进程退出证据。执行仍需外层驱动证实进程树退出后才允许发送 `processStopped`。活动读取受整轮时限约束，不把正常长思考错误套用 30 秒握手超时。

当前已注册 `device_codex`，CLI 支持显式 `--execute codex --accept-estimated-budget`。设备调度、网页选择和以下可信启动/配置与登录隔离已接线，部署默认不开启。协议代码自身不是 OS 沙箱，也不能替代启动限制；Codex 不具有供应商美元硬预算能力。

验证采用受控事件及真实 Python 子进程 stdio 对端，覆盖真实工具往返、当前轮身份校验、重复请求、失败、中断、公开摘要、隐藏推理过滤、流量上限和进程退出。另用本机 `codex-cli 0.141.0` 的 `app-server generate-json-schema --experimental` 输出校验实际发出的初始化、线程、轮次及动态工具响应形状；此证据只证明协议格式兼容，不证明该 CLI/真实账号可安全执行脑图任务。

### Codex 可信本地驱动（默认关闭）

`codex_driver.py`、`codex_policy.py` 将 OpenDesign 的“一轮一进程、JSON-RPC 生命周期、事件回传、退出确认”适配为本项目受限工具协议，不复制其广泛的本机执行权限：

- **可信程序**：可选依赖锁定 `openai-codex-cli-bin==0.147.0`；执行随包绝对路径，初始化再次核对真实运行版本，不回退到 PATH 上扫描到的其他版本。构造/扫描不读取登录；远端 offer 不得指定命令、环境、目录、提供商或凭据。

### 本机运行记录与启动前崩溃恢复

伴随程序新增 `run_recovery.py`，参考 OpenDesign `agent-process.ts` 的持久所有权与启动回收；Claude、Codex、Kimi 的实际执行和 Kimi 版本探测均通过登记启动器创建。`OwnedProcess` 继续负责正常运行/取消时的进程组退出；新机制负责下一次显式启动执行通道之前的资源核验，二者不替换平台工具与任务合同。

- 每轮目录固定在本机当前用户的 `~/.local/state/mindmap-agent-bridge/runs/<UUID>`，目录 `0700`，记录和锁文件 `0600`。记录只保存 Agent 类型、owner 与子进程 PID/创建时间，**不保存提示词、脑图、命令参数或凭据**；目录内部仍可能包含 CLI 的本轮认证副本与运行数据，不应分享或同步。
- 父进程先建立 owner 和 pending 启动记录；无 shell 的 Python 启动器核对 owner、父子关系和独立进程组，再在注册锁内原子落盘自身 PID/创建时间，成功后才 `exec` 实际 CLI。这样模型进程不能先于登记执行；写入失败、重复启动槽或 owner 已退出均直接退出，不执行目标程序。
- `run --execute …` 先完成恢复，再建立发现/执行连接。owner 存活与独占锁均用于避免干扰另一条桥接。恢复只处理已退出 owner 的记录；信号前核对精确创建时间及进程组，先 TERM，必要时 KILL。只有确认停止后才删除该轮准确的目录，不递归删除 runs 根目录。
- 本次恢复开始前组长已经消失、但仍有活跃组成员时，缺乏持久身份见证，不能排除进程组复用：保留并报告未确认。PID 不匹配、文件/目录权限不安全、符号链接、未知字段、重复 JSON 键、损坏/过深 JSON、记录过多及终止失败同样拒绝猜测；有未解决记录时不建立新的执行连接。
- 注册锁把 bootstrap 写入与恢复清理串行化；正常执行期的 owner 锁不传入 CLI。文件/目录所有权检查和删除前 inode 检查用于避免误删；这些不是针对同 UID 恶意软件或恶意 CLI 的 OS 沙箱保证。
- 恢复不会发送旧提示词、重新调用模型、恢复供应商会话、修改业务脑图或补造服务端停止回执。执行前发现不可确认资源会阻止连接并提示本机检查；旧任务仍应按原错误/保存回执处理，用户明确重试才产生新任务。
