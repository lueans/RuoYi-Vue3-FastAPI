# AI 脑图模版与附件实现及验收计划

## 产品约定

`+` 菜单包含“添加附件”和“添加模版”。附件选择本地文件；模版在菜单右侧展开，可搜索当前用户有查看权限、位于“模版/模板”目录及子目录中的云端脑图。

模版仅限定可用的视觉样式、节点关系模式与标签使用。主题、事实、节点文本、覆盖范围和详略由本轮需求及内容附件决定。模型可以复用关系模式扩展新节点，不照抄示例事实，也不固定示例章节名称或节点数量。全局任务预算和编辑授权仍有效。

模版原图保持不变。选择时记录来源和版本；提交时服务端复核权限及版本，冻结本轮格式快照。模型只能引用快照中的角色，不能自行提交任意格式或扩大标签绑定权限。运行、预览、直写、保存、恢复和重试必须使用一致的受信快照。

## 已确认并修复的稳定性问题

- 标签渲染器此前忽略标签定义中的默认位置和对齐方式；现在节点独立设置优先，否则继承定义。
- 模版附件此前丢弃标签信息；现在保留其身份、受支持样式和局部位置，并将节点文字、备注明确标为示例。
- 登录失效此前只防并发弹窗，取消后再次 401 会重新弹出。现在按认证会话锁定失效状态，并在请求发送前阻断同一失效会话的后续认证请求。
- 登录失效清理须等待草稿保护完成；旧请求的 401 和旧弹窗确认不能清除后来登录的新会话。备份失败时保留只读画布和显式重试入口。
- 实际页面还复现了独立的协作循环：同版本 `yjs_lineage_changed` → HTTP 拉取成功 → 重建连接 → 再次拒绝。原先每轮弹两个成功提示，且 HTTP 成功会重置重试预算。现去掉误导的后台成功提示，独立限制 30 秒内的协作恢复次数；连续失败暂停同步并保留画布，支持显式重试。根因是空 Y.Doc 迁移 schema 提前发送缺少 lineage 的内部 update；现在等待正式 seed 建立基线。4 个真实 Y.Doc 新用例及全套 234 个 Yjs 用例通过；实际页面 130 已恢复协作在线并持续稳定。
- 真实模型验收发现现有 DashScope/kimi-k2.7-code 配置 temperature=2.0，被供应商以 HTTP 400 拒绝（要求小于 2）。保留用户模型配置，改为明确 `AI_MODEL_CONFIG_INVALID` 错误及温度提示；供应商原始错误和凭据不会进入用户消息。已用原有温度 0.2 的本机 Qwen 模型验证可执行工具。
- 模版深度超出当前任务上限时提示用户提高层级，不自动改变预算、不限制发送；移除模版或提高上限后提示消失。实际模版全树最深 8 层，验收产物复用其中的 7 层用例链。
- 失败终态不再显示“Agent 仍会继续运行”；迟到的草稿响应也不能恢复该提示。已选模版时目标布局输入禁用，并解释整图采用模版布局、局部编辑保持原布局。

## 格式执行链路

1. 客户端只提交 `templateSource: { mindmapId, contentRevision }`，不接受客户端格式 profile 作为授权依据。
2. 服务端从规范脑图读取格式，校验目录、阅读权限和版本，并将冻结 profile 作为内部请求状态持久化。
3. 模型选择服务端提供的节点角色；平台应用允许的样式、标签局部位置和关系。整图布局/主题仅能作用于整图授权范围。
4. 预览、提案、直写和最终保存共用格式校验，禁止只在最终导出或画布展示时补丁式应用。
5. 不可绑定的模版标签保持现有权限边界，给出用户可理解的处理结果，不静默用同名异样式标签替代。
