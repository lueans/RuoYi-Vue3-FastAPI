# 脑图文件、节点与统一标签改造完成度审计

审计日期：2026-08-18（持续审计）

## 结论

产品设计中的 Phase 1～3 和 Phase 4 的业务能力已完成：结构化节点主数据、simple-mind-map 兼容编解码、增量保存、Yjs revision 防护、统一标签传播与生命周期、历史标签快照、节点搜索、标签筛选和使用明细均已有后端契约及前端入口。

旧模型物理下线仍按设计保留在灰度阶段，不应在本次变更中直接删除：当前 `mindmap` 表兼任 `mindmap_file`，`node_tree` 作为兼容/回滚快照继续双写。待生产影子比对和稳定观察完成后，再执行物理重命名与旧字段删除。

## 本轮补齐的问题

1. 增加标签停用、全局替换、使用明细和显式解绑归档接口。
2. 标签替换会删除同节点重复关系；替换和解绑会推进文件 revision、写变更日志并废弃旧 Yjs 缓存。
3. 删除判断改为查询真实关系数量，不再依赖可能滞后的统计缓存。
4. 历史版本增加不可变标签快照；预览冻结旧定义，恢复后重新读取当前统一标签定义。
5. 正式版本改从结构化节点主数据生成，避免旧 `node_tree` 快照滞后。
6. 标签使用量统计从逐标签多次查询优化为一次聚合查询。
7. 新增节点搜索、标签筛选和使用明细分页接口，并接入编辑器搜索面板。
8. 三份结构迁移改为 information_schema 守卫，可安全重复执行。
9. WebSocket 房间广播接入 Redis Pub/Sub，支持多 worker、事件去重、订阅重连和单实例降级。
10. 在线成员改为带过期心跳的 Redis ZSET，并以权威成员快照处理同一用户多标签页。
11. 增加 20,000 节点、256 层安全上限，以及 5,000 节点 P95 性能基线。
12. 结构化节点首次写入改为按树层级、每 1,000 条分块批量插入并批量回读主键，保留父子外键顺序。
13. 前端 1,000 节点以上默认启用可视区域渲染，并关闭高成本的文字实时重排。
14. 标签绑定改为 executemany 批量写入，1,000 节点/3,000 绑定的增量保存 SQL 从约 3,011 条降至 12 条。
15. 增加新旧树只读影子校验器，忽略全局标签名称/样式副本与随机 UID，按稳定树路径比较节点、顺序、标签绑定、关联线、概要、外框和资源。
16. 增加真实数据库性能基准脚本，所有测试数据均在外层事务结束时回滚，并支持阈值失败退出。
17. Yjs 同步补齐删除属性、递归删除子树、节点移动后 `parentUid` 重算，并将布局、主题和视图状态纳入协作文档元数据。
18. 文件布局、主题和视图分别进入独立冲突域；文件级修改不再重写节点表，与并发节点修改可自动合并。
19. 脑图列表新增统一标签筛选；节点搜索用递归 CTE 一次返回完整节点路径，前端同步展示路径上下文。
20. 结构化持久化入口增加标签绑定安全边界：拒绝他人私有标签、失效 ID/UUID 和新增的停用/归档标签；已停用标签仍可在原节点保留。
21. 修复字段标签建议的前后端字段契约错位，避免字段名空白和不同字段单选状态串扰；建议查询由最多 61 次 SQL 收敛为 2 次，并过滤已停用/归档标签的选项。
22. 新增脑图标签可携带性服务：协作者复制、模板发布和旧模板使用时，启用的全局标签继续引用，不可见私有标签/停用标签/失效引用保留名称、样式和局部位置后转为目标所有者的可用标签。
23. 版本恢复允许重新建立已停用标签的历史绑定，已归档/已删除标签转为迁移标签；正式版本编号改为在文件行锁内分配，删除正式版本会同步回收列表版本计数。
24. 版本预览期间同时暂停 Yjs、自动保存和节点操作队列，画布切换为只读；退出预览后恢复原状态，避免历史数据被后续编辑意外提交。创建正式版本前必须先成功刷新当前待保存修改。
25. 取消未实现的“匿名可编辑分享”伪能力：公开链接明确为只读，后端拒绝编辑型分享请求，需要写入时引导使用有身份和权限的协作者功能。
26. 导入新增 20MB 大小上限、同源 URL HTTP 状态校验、脑图根结构校验和 FileReader 失败提示，拒绝 `null`、数组和任意 JSON 冒充脑图。
27. 公开分享预览复用大文档节点统计和性能模式，1,000 节点以上不再启用高成本文字实时重排。
28. 节点并发协议拆分为属性、父子边和同父顺序冲突域：同一父节点下新增不同子节点按原兄弟锚点间隙稳定合并，同一节点属性、同一父子边、同父重排以及重排与增删并发、删除/后代编辑仍会明确冲突。
29. 节点保存改为始终在服务端当前树上应用本批操作，客户端 `nodeTree` 仅作为操作载荷来源；Yjs 已显示但没有进入本批日志的远端节点不会被隐式写入，保证物化树与变更日志一致。
30. 补齐实时节点选区 awareness：协作者当前激活节点会显示其头像/名称，切换、版本预览暂停、断线和离开房间都会清理；服务端覆盖认证身份、去重并限制单次最多 100 个节点 UID。
31. Yjs 缓存由“同 revision 后写覆盖”升级为最多 32 个来源的二进制状态包；重连握手逐个应用并由 Yjs 合并并发状态，相同完整状态自动折叠，损坏缓存可由下一份合法状态自愈，旧单状态格式继续兼容。
32. 标签定义实时事件增加 `definitionRevision` 单调性校验；乱序到达或重复的旧事件不会把新名称、样式和状态回滚。
33. 字段管理增加影响预览，保存默认样式前展示受影响文件与节点；多选字段切换单选前会统计真实冲突节点并由前后端共同阻止非法转换。元数据未改变样式时不再批量递增标签版本。
34. 字段默认样式和标签覆盖样式不再互相物化覆盖：字段变更保留标签个性化属性，在线事件发送最终合并样式；历史版本按 `tagId + fieldId + optionId` 冻结字段继承后的最终外观。
35. Yjs 房间首次持久化增加唯一键竞争重试：两个连接同时创建缓存行时，失败方会重新锁定胜者记录并合并自身状态，避免首批协作内容丢失。
36. Yjs 增加独立 `tagDefinitions` 映射：节点仍只同步 `tagId/fieldId/optionId`，新绑定标签的可渲染定义通过独立缓存随房间状态合并，远端用户和重连会话不再出现空名称标签。
37. 标签定义事件会同步刷新已打开的标签选择器和属性面板；普通用户面对无权管理的全局标签/字段时直接进入只读状态，仍可执行节点级位置、对齐和移除操作。
38. WebSocket 对 Yjs update/state 使用严格 Base64 校验和 5MB/15MB 解码上限，非法载荷不再广播或持久化并向客户端暴露协议错误；标签 Key 作为稳定外部标识，非管理员不能修改。
39. 标签样式继承在文件加载、节点搜索、标签列表/详情/建议、复制/模板携带、停用与替换实时事件中统一解析；数据库只保存标签覆盖值，字段默认样式不再被复制成第二份主数据。
40. 标签替换会在单个 Yjs 定义事务中原子删除源定义并写入目标定义；节点协作数据只替换 `tagId`，继续保留字段绑定和节点级布局，不再意外复制名称、样式等定义字段。
41. Yjs 按产品设计新增 `relations`、`summaries`、`groups`、`assets` 顶层集合，关联线、概要、外框和图片字典不再嵌入节点冲突域；旧版节点内协作状态会自动迁移，删除节点时会剔除悬空关联 UID。
42. 编辑器顶栏补齐键盘可操作的重命名入口、返回按钮语义、保存/协作状态 `aria-live` 播报和画布区域标签，读屏与纯键盘用户能感知核心编辑状态。
43. 自动保存协议增加 `relation/summary/group/asset.upsert|delete` 独立操作域，与 Yjs 顶层集合保持一致；同源不同关联线可并发合并，普通文本更新不会携带过期关系覆盖服务端，外框成员连续性和跨节点 UID 在物化前统一校验。
44. 标签绑定按设计拆为 `node.tag.bind/unbind/reorder` 独立操作域：节点文本与标签修改不再相互覆盖，同节点不同标签可自动合并，同一绑定、标签重排与绑定增删会精确冲突；操作仅携带标签身份和局部布局，全局名称/样式继续由标签定义统一生效，旧裸标签仍走兼容路径。
45. 统一标签治理页补齐名称/Key/描述搜索、范围/状态/分类/字段组合筛选、真实样式预览、所属字段、说明、使用统计、更新时间和修改审计；标签编辑支持分类、说明及停用恢复。列表字段上下文使用一次批量查询，分类写入增加全局/私有作用域校验，拒绝引用他人私有分类。
46. 标签替换新增绑定上下文预检：同一节点的普通标签与字段/选项标签不会再被误判为可去重，发现上下文冲突时明确阻止替换；批量替换/解绑的文件编辑权限改为一次集合查询，批量归档的标签、使用量、影响文件和标签更新均改为集合 SQL。持久化提交后的 WebSocket 通知失败只记录降级告警，不再把已成功操作误报为失败。
47. 脑图批量删除增加正整数解析、重复 ID 消除和单次 100 个上限；所有权校验由逐文件查询改为一次集合查询，仍严格保持仅所有者可删除，并在任何关联清理前阻断越权请求。
48. 文件删除补齐在线协作终止协议：提交后广播 `document_deleted`，本实例与 Redis 其他 worker 均清理在线成员并以 4004 关闭房间；前端立即停止 Yjs、自动保存、重试和本地草稿，提示后返回列表。Yjs 持久化增加 `del_flag='0'` 防线，旧客户端或关闭竞态不能重建已删除文件的协作缓存。
49. 协作者降为只读或被移除后，权限变更提交成功即通过 Redis 向所有 worker 定向发送 `access_revoked`，只关闭目标用户的全部标签页，其他协作者与房间 revision 保持在线；前端在终止写入前自动下载未同步 JSON 备份。强制关闭连接禁止在 WebSocket `finally` 回写 Yjs，心跳每 30 秒从数据库复核编辑权限，Redis 异常时仍能最终撤销旧连接。协作者权限输入严格限制为 `0|1`。
50. 协作者发现链路补齐“与我共享”列表：服务端按当前登录用户关联协作表，返回所有者、有效权限、`isOwner/canEdit`；详情与列表使用同一权限口径。前端默认在权限响应前保持只读，只读协作者不启动 Yjs、自动保存或本地草稿，也无法通过导航栏切回编辑模式；共享和协作者管理入口仅对所有者显示。
51. 编辑页路由生命周期收口：缺失、非正整数或超出 JavaScript 安全整数范围的文件 ID 不再意外启动本地脑图；同路由切换文件 ID 时以 `key` 完整重建编辑器。详情不存在、访问被拒绝或网络失败时展示稳定错误页而不是空白画布；从共享列表进入后，返回和终止事件均保留“与我共享”上下文。
52. 结构化迁移补齐文件级审计和提交门禁：新增 `mindmap_migration_record`，按文件幂等记录批次、`migrated/failed`、新旧 SHA-256、错误与起止时间。每个文件在同一事务内写入新表、回读并执行规范化树影子比对，差异即整体回滚并另事务标记失败，旧 `node_tree` 继续作为回退数据。同时修复迁移 SQL 过早删除幂等辅助过程的执行顺序错误。
53. 迁移失败状态接入运行时保护：列表和详情返回 `contentState=migration_failed`，并将有效 `canEdit` 强制降为假；所有复用统一编辑权限检查的写入端点均拒绝失败文件。前端依然从旧 `node_tree` 显示内容，但显示“迁移保护”标识和不可关闭说明，不启动任何写入链路；迁移重跑成功覆盖记录后自动恢复编辑。
54. 增量保存请求契约收口：操作类型由前后端约定集合统一约束，未知操作不再被静默忽略后仍推进 revision；节点、标签、跨节点实体操作必须携带对应身份和载荷，布局/主题操作必须同时提交目标值，避免空变更污染日志、版本和协作状态。
55. 公开分享生命周期与预览体验补齐：后端拒绝非法令牌和过去时间，统一处理浏览器带时区日期；迁移失败文件明确回退旧快照。分享管理页区分有效、过期、禁用和时间异常，禁止复制无效链接。公开预览修复“加载态内提前初始化导致画布永久空白”，并增加缩放比例、适应画布、全屏、键盘快捷键、响应式控制栏和可重试错误态。
56. 公开预览插件依赖与编辑器解耦：不再通过 `usePlugins.js` 静态引入导出、XMind/XML、绘制、搜索、演示等完整编辑能力；触屏能力常驻，关联线、外框、公式和思维导图专业布局根据实际节点数据动态加载。增加架构边界测试，阻止编辑/导出插件重新进入公开预览入口。
57. 登录注销改为幂等容错：损坏、缺失或旧格式 Token 不再让 `/logout` 抛出 JWT 解码异常和 500，登录页不会因遗留 `undefined` Token 卡在加载状态。
58. 脑图权限兼容新旧命名空间：后端接口同时接受 `mindmap:mindmap:*` 与历史 `mindmap:*`，前端文件操作与目录加载使用同一兼容口径；普通角色没有目录权限时仍可正常使用“我的脑图”和“与我共享”。
59. 协作者列表补齐用户身份关联查询，头像、用户名和昵称由 `sys_user` 返回，不再显示匿名问号；真实双账号验证新增、降级只读、在线撤权和最终移除均生效。
60. Yjs 远端应用保护覆盖到 `node_tree_render_end`：异步渲染期间产生的 `data_change/view_data_change` 不会再被误记为本地修改或生成伪草稿；渲染期间到达的后续远端更新会排队重放，不再静默丢失。
61. 无缓存协作房间新增分布式种子租约：已有在线客户端优先提供完整状态；全新房间通过 Redis `SET NX` 或单实例锁选出唯一初始化者，避免同一 revision 多客户端独立创建嵌套 Yjs 类型。

Schema 发布门禁从“同名对象存在”提升为“定义一致”：关键索引同时校验列顺序与唯一性，模板分类外键同时校验本地列、目标表和目标列，避免错误的同名索引或外键被误报为 `READY`。对应 SQL 同步具备定义收敛能力：同名对象错误时先精确删除再按契约重建，不再因“名称已存在”永久跳过；模板历史数据清理在 DDL 前显式提交，避免用事务包裹 MySQL 隐式提交 DDL 造成原子性错觉。新增只读迁移计划器，将缺失产物按固定依赖顺序归并为实际 SQL 文件，输出文件 SHA-256、用途和缺失对象；遇到未知迁移、文件缺失或空文件时失败关闭。权限命名空间属于业务数据迁移，无法从结构元数据可靠推断，因此始终作为人工复核项单独输出。当前开发库实测仍为 7 个缺失产物，但已收敛为归档、目录、模板 3 个有序迁移文件；整个计划过程不执行 DDL/DML，也不输出连接凭据。

107. 只读权限从界面门禁下沉到 simple-mind-map 命令总线：只允许节点定位、选中和展开/收起等浏览命令，文本修改、节点增删移动、样式、历史回退和布局重置等写命令统一拒绝并发出可观测事件，因此快捷键、插件或遗漏的 UI 入口也不能制造无法保存的本地幽灵变更。只读大纲仍可浏览和定位，但编辑入口、`contenteditable`、拖拽及所有节点级写函数均有独立防线。权限撤销、会话失效、文件归档或删除时，编辑器先同步关闭大纲并提交普通/富文本节点、关联线和外框的活动文本框，再判断脏状态、写入草稿并尝试下载 JSON，最后立即关闭侧栏并将 Store 和核心实例锁定为只读；提交活动输入期间禁止向已经失效的服务端写入，避免最后一次输入丢失或撤权后的竞态保存。
108. 编辑会话身份补齐文件与访问模式维度：编辑器实例键由单独文件 ID 改为 `文件 ID + edit/readonly`，同一路由修改只读参数时会完整销毁旧核心、Yjs 和事件监听，再按新权限重新加载，不再出现标题栏已只读但画布仍保留写能力的状态分裂。同一路由切换文件或访问模式现在与离开编辑页复用同一保存守卫：先刷新待保存修改，失败时根据本地草稿状态给出准确风险提示，由用户决定留在原会话或继续；路由获准后才重置标题、服务端权限、归档和迁移保护状态。只改变列表来源等非会话查询参数不会无谓重建编辑器。
109. 编辑器首屏由隐式“详情已返回”升级为显式 ready 协议：服务端权限返回后仍保持加载遮罩，直到 simple-mind-map 首次节点树渲染完成、动态插件安装、Yjs/保存监听和通用事件全部绑定后才展示命令栏、导航工具和画布。加载卡片提供桌面/窄屏自适应、明暗主题、`role=status`、`aria-live` 和忙碌状态，并区分“获取文件与权限”和“初始化画布与协作能力”两个阶段。画布容器不可用、核心构造异常、实例提前销毁或首次渲染超过 10 秒都会清理监听并转为明确失败页，不再留下永久空白画布或提前可点击的无效操作。
110. 编辑器加载失败从终点升级为可恢复状态：错误页新增主操作“重新加载”和次操作“返回脑图列表”，桌面横向排列、窄屏纵向全宽，不再要求用户手动刷新整个后台。重试保留当前文件 URL 与访问模式，但清空失败实例引用、ready、服务端权限、所有者、标题、归档和迁移保护等会话派生状态，并通过独立 nonce 创建全新的编辑器实例；旧实例的 Yjs、计时器和事件监听在错误页切换时按组件生命周期销毁。无效文件 ID 不提供无意义重试，重复点击因错误页立即退出而不会并发创建多个实例。
111. 编辑器异步初始化和运行期重载增加统一的会话级取消边界：每次挂载创建独立 `AbortController` 并把 `signal` 传入详情、协作状态恢复、远端版本重置和冲突重载请求，卸载时立即中止；详情响应、IndexedDB 草稿读取、草稿选择、容器等待及重载渲染等每个异步边界后都重新确认组件仍存活、核心实例仍存在且会话未取消，旧文件不能再向新页面发送标题、权限、加载错误、ready 或成功提示。草稿恢复与冲突处理确认框明确归属当前会话，路由切换时主动关闭；冲突副本只在确认当前会话仍有效后才下载，避免用户在文件 B 上误处理或备份文件 A。请求拦截器把 Axios `ERR_CANCELED` 识别为正常控制流，不再弹出“canceled”错误提示，同时保留真实超时和网络失败反馈。专项测试覆盖快速切换时的请求信号、中止、迟到响应隔离、两类弹窗关闭、运行期重载返回值和取消错误静默。
112. 保存冲突恢复升级为会话内单飞事务：自动保存捕获冲突与用户点击“处理冲突”并发发生时复用同一个 Promise，只能出现一个确认框、一次安全副本下载和一次权威详情重载，事务结束后才释放互斥。权限撤销、登录失效、文件归档或删除不仅锁定画布，还会立即中止会话读取并关闭草稿/冲突弹窗；关闭产生的 Promise 结果按主动取消处理，不再提示旧会话错误或继续下载副本。批量保存响应返回后会在应用 revision、清除操作队列或本地草稿前再次检查会话与核心实例，终止或卸载期间迟到的响应不得改写状态；服务端可能已接受的在途请求仍由既有幂等 mutation ID 和后续权威加载对账，不用“前端取消”等同于服务端回滚。
113. 本地草稿队列增加版本化写入和条件清理，修复“页面卸载同步备份已经写入，但旧 IndexedDB 保存/删除任务随后到达并覆盖或移除新副本”的数据丢失窗口。每次文档快照在入队时冻结单调递增的 `updatedAt` 并携带唯一 `writeId`，而不是等队列真正执行时才取时间；IndexedDB 在同一读写事务内读取现存记录，只允许不旧于现存版本的记录覆盖，localStorage 回退采用同一新版本优先规则。成功写入 IndexedDB 后只清理由该记录覆盖的旧回退副本，不能删除时间更新的同步卸载备份。云端保存开始时建立草稿清理截止时间，成功后仅删除该时间及以前的记录；保存期间产生的新编辑草稿会获得更大的时间并被保留。草稿中心的用户显式删除仍保持无条件语义。专项测试复现迟到旧写入和迟到条件删除，确认更新副本持续可恢复。
114. 草稿记录创建时对规范化文档执行 JSON 快照复制，隔离调用方后续修改；即使 IndexedDB 打开或事务执行期间原始节点树、插件配置继续变化，已赋予时间版本的记录内容也保持不变。稳定序列化从递归拼接改为显式栈的规范 JSON 输出，对对象键排序、保持数组顺序、按 JSON 语义处理空值并检测活动路径循环引用；5,000 层合法数据不再触发 `Maximum call stack size exceeded`。该序列化器同时服务草稿等价判断、文件元数据差异和节点/跨节点操作检测，完整回归确认替换后各冲突域行为一致。
115. 本地草稿键从单一的“用户 + 文件”扩展为“用户 + 文件 + 编辑会话”，同一账号在两个浏览器标签页编辑同一脑图时各自保留独立记录，一个窗口云端保存只按自己的会话 ID 和时间截止清理，不再覆盖或删除另一个窗口的未提交内容。旧版双段键和无 `sessionId` 记录继续参与列表、最新草稿选择与显式删除，无需 IndexedDB 结构迁移。草稿中心按记录键展示、继续和删除，路由携带受长度限制的 `draftKey`；编辑会话身份包含该键，切换恢复目标会经过保存守卫并重建实例。选择恢复其他窗口草稿后，编辑器先为当前会话建立新副本，云端保存成功才按原记录键和原更新时间条件清理来源；来源窗口若已写出更新版本则保留。列表用“独立编辑窗口/兼容草稿”说明记录类型，减少重复文件草稿的歧义。
116. 多记录草稿中心补齐视觉辨识和可访问性：每个会话从不暴露完整内部 ID 的尾部字符生成稳定六位窗口短标识，并以品牌色胶囊徽标展示；旧版记录使用中性“兼容草稿”徽标，同名、同文件、相近时间的多份草稿仍可区分。下载、继续和删除按钮的可访问名称都包含草稿名与窗口来源，读屏和语音控制不再遇到多个同名操作。720px 以下卡片纵向排列，操作区改为两列等宽网格，危险删除独占整行；对话框保持 `100vw - 24px` 安全边距、滚动列表高度上限和可换行元数据，在 390px 视口不会横向溢出。
117. 本地草稿持久化结果成为保存反馈的唯一事实来源：离线、云端重试和重试耗尽流程先显示“待保存”，只有 IndexedDB 或 localStorage 实际返回 `saved: true` 后才宣告“已保存到本地草稿”，不再把存储被禁用、配额耗尽或超出 2 MiB 回退上限误报为安全。双存储均失败时保存状态进入错误态并提供“保护修改”，首次点击会重试本地持久化；在线时成功后立即继续云端保存，离线时明确等待恢复联网。重试仍失败则自动下载带安全文件名的 JSON 备份，下载也失败时要求保持页面开启并手工复制重要内容。失败通知在同一连续故障期间去重，后续真实持久化成功会恢复正常状态。新增超大草稿真实失败和编辑器反馈契约测试，确保任何成功文案都以存储结果为前提。
118. 管理列表补齐窄屏操作和前端权限执行边界：标签治理和脑图列表的操作列固定在右侧，390px 视口无需滚动 1,350px 宽表格即可查看影响、编辑或打开管理菜单；标签五个动作收敛为“影响 + 管理”组合，操作列由 300px 缩至 150px，读屏名称包含具体标签名。脑图列表的 220px 操作列同样固定，移动端仍保留查看、编辑和更多操作。文件夹图标触发器由不可命名的图标改为原生按钮，支持清晰名称、键盘焦点和 `focus-within` 揭示。下拉菜单项不再挂载无法作用于 Element Plus Fragment 根节点的 `v-hasPermi` 指令，改用统一响应式权限计算控制渲染，并在文件夹/脑图命令分发入口再次校验权限与所有权；消除每行重复产生的 Vue 运行时警告。标签分页切换到当前 `size="small"` API，消除 Element Plus 3.0 弃用告警。

Schema 预检接入可选 Docker 发布门禁：`docker-compose.my.yml` 新增仅在 `release-check` profile 启用的 `ruoyi-mindmap-schema-check` 一次性服务，复用后端镜像，在 MySQL 健康后执行只读 `verify_mindmap_schema --env=dockermy`。普通 `docker compose up` 和后端启动不依赖门禁，滚动升级期间不会因缺少新表直接阻断旧版本运行；门禁只通过退出码与 `READY/NOT_READY` 报告发布前状态，不执行 DDL/DML。README 固化“计划迁移 → 人工审核 SQL 与权限命名空间 → 受控执行 → READY 复验”的容器内和宿主机命令，契约测试同时锁定 profile、健康依赖、只读脚本和普通启动隔离。

122. 搜索替换语义与标签筛选状态机完成收口：simple-mind-map 的纯文本和富文本替换统一复用字面量助手，搜索词中的 `.*+?[]()` 等字符不再被解释为正则表达式，替换内容中的 `$&`、`$1` 等模板也按用户原文写入，空搜索不会插入内容。标签建议加载具备加载态、失败提示与重试、最新请求获胜以及面板关闭/卸载失效边界；清空关键词或标签后立即清除旧结果，避免保留已经不符合条件的服务端命中。建议项按稳定标签 ID 去重，同名标签以“作用域 + tagKey”区分显示但仍以 ID 作为筛选值；筛选控件补齐可访问名称，错误状态可被辅助技术感知。
