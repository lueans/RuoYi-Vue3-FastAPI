# AI 脑图 Agent 产品与交互设计（设计基线 v2）

日期：2026-09-20
范围：现有 Web 脑图编辑器中的 AI 协作体验、任务运行治理和 Agent 能力边界；本文件定义产品行为与实现契约，不启动界面或接口实现。

V3 的 Agent SDK、Skills、插件和 MCP 扩展平台已拆分到 [V3 扩展平台设计](./2026-09-20-mindmap-ai-agent-product-design-v3.md)，本文件保留 V2 的核心任务、实时编辑、状态、变更和恢复设计。

交互 Review 已合入本文，不再单独维护重复报告。本文保留阶段性产品规划；当前已实现的云端权威、AI 编辑只读及逐节点逐字播放规则，以 [AI 脑图流式展示契约](../../ai-mindmap-streaming.md) 为准。

## 1. 产品判断

AI 的工作对象是**当前脑图**，对话是给 AI 任务、补充约束与追溯决策的入口。用户应能像指挥一位正在编辑脑图的同事那样工作：说出目标，看见对方逐步修改，随时纠正，离开后回来继续，完成后直接使用结果，需要时撤销这一轮的全部修改。

每句话都不应被强制映射到“创建、扩展、改写、整理”中的某个固定表单流程。Agent 可以根据目标和当前上下文自行选择阅读、解释、编辑、检查、提问或结束；这些动作可以在同一轮内反复交替。界面只呈现对用户有用的意图、进度、变更与控制权。

## 2. 已确认的当前基线

- 当前脑图 `132` 为“购物车测试用例设计”，根主题“购物车功能测试用例”，51 个节点、6 个一级分支：正常、异常、边界、兼容性、性能、安全测试。它已经是一份可继续编辑的真实工作成果，不应在每轮 AI 对话中重建根节点或另起一层“AI 结果”。
- 当前 AI 面板已有会话历史、Agent/模型选择、来源范围、生成方式、实时草稿事件、失败重试、继续调整、默认采纳和整轮撤销。能力较全，但入口被设置项和状态分支切碎。用户需要理解“任务类型、目标、生成方式、来源、重试、续写、提案”等内部概念，才能完成一次自然的协作。
- 本轮没有对页面进行视觉走查。浏览器中的本地编辑页因 `getMindmapAiNodeCenterOffset` 导出缺失停在空白状态；本设计以当前脑图数据、界面源码和已有设计系统为依据。视觉布局和实际动效待后续单独验证。

## 3. 用户要完成的事

| 意图 | 用户语言示例 | 期望结果 |
| --- | --- | --- |
| 理解 | “购物车这张图目前覆盖了哪些高风险场景？” | 基于脑图回答，并可定位证据节点，不改图 |
| 补充 | “把优惠券自动应用的异常与边界补齐” | 在当前相应分支连续补节点，不重建整图 |
| 改造 | “正常流程和异常流程有重复，整理一下” | 先识别重复，再逐步移动、合并或改写节点 |
| 检查 | “找出还缺少的移动端测试点” | 给出缺口与理由；用户说“补上”时接着编辑 |
| 过程干预 | “先别动安全测试，优先处理库存不足” | 在安全边界处吸收新约束，调整本轮工作方向 |
| 回退 | “刚才这一轮改得不合适” | 一次撤销这一轮 AI 修改，其他人的修改保留 |

成功体验是：用户只需描述目标，Agent 能理解“这张图、这个分支、刚才新增的点”，并用画布上的真实变化回应。

### 3.1 软件整体能力边界

成熟的 AI 脑图产品仍需先是一款可靠的脑图软件。产品能力按“持续可用的基础能力”和“由 Agent 调用的能力”组织，而不是把每个 AI 场景做成独立向导。

| 能力层 | 面向用户的成熟度要求 | Agent 的接入方式 |
| --- | --- | --- |
| 脑图编辑 | 快速建点、键盘操作、拖拽、布局与样式、备注/链接/标签、搜索与大图导航 | 通过同一套受约束的节点操作修改，结果立即成为普通可编辑节点 |
| 文档管理 | 多脑图/多画布、导入导出、自动保存、版本历史、恢复 | 能引用用户授权的脑图或文件；产出沿用标准文档格式 |
| 协作 | 评论、共享、权限、多人实时编辑、冲突提示 | AI 作为有归属的协作者，其操作、范围和撤销记录可追踪 |
| AI 工作 | 问答、生成、补充、重组、审查、解释变更、跨轮继续 | 一个自然语言入口，按当前目标动态组合阅读、编辑和检查 |
| 可信内容 | 来源与依据、结构校验、重复检查、敏感数据边界 | 说明引用了哪些授权资料，不能把推断包装成已有事实 |

首要用户可以是测试人员和测试负责人，也应支持计划、研究、学习和知识整理。购物车用例脑图作为首个真实验收样本，产品对象不能硬编码为“测试用例生成器”。

### 3.2 当前三个 Agent 的定位

当前系统有三个 Agent 入口，但它们是三种运行时适配器，不应让用户承担三套不同的脑图交互：

| Agent | 当前 SDK/运行方式 | 已有能力基线 | 产品定位 | 扩展边界 |
| --- | --- | --- | --- | --- |
| 项目自定义 Agent | Agno + 项目自研脑图工具 | 实时流式、结构化输出、脑图工具约束；当前不依赖供应商会话 | 默认的实时脑图编辑 Agent，优先承担低风险 R1 操作 | 共享 Skills、受控 MCP；不能通过 Skill 绕过脑图工具契约 |
| Codex SDK | OpenAI Codex SDK/受限 Worker | 会话恢复、实时流式、工具调用、独立会话快照 | 长任务、复杂整理、需要更强规划和外部工具时使用 | 通过统一 Agent SDK 和受限 MCP Bridge 接入；不能直接覆盖脑图文档 |
| Claude SDK | Claude Agent SDK/受限本地运行 | 会话恢复、实时流式、工具调用、结构化结果 | 多步骤分析、资料理解和复杂重组 | 仅暴露项目允许的脑图 MCP 工具；内置文件、Shell 和网络能力默认关闭 |

三种 Agent 都必须遵守相同的 `AgentRunContext`、脑图工具契约、权限范围、风险审批、事件协议和变更组规则。用户选择 Agent 只改变模型、会话、工具实现和能力标签，不改变画布结果语义、撤销语义或安全边界。

每个 Agent 的清单需要公开声明：`agentKey`、Adapter/SDK 版本、模型、会话、流式、取消、结构化输出、Skills、Plugins、MCP、后台恢复、沙箱、网络、数据区域、认证方式、支持的意图和输入类型。当前自研 Agent 的 `supports_sessions=false` 必须在任务中心显示为“由平台检查点恢复”；Codex 和 Claude 的供应商会话不能替代平台任务检查点。

## 4. 交互原则

1. **画布是真相来源。** AI 修改直接出现在当前脑图组件；对话卡片解释变化，不能拿一个与画布脱节的预览层代替实际工作区。
2. **自然语言先于配置。** 默认由 Agent 推断“回答还是编辑、修改哪些节点、如何拆解步骤”。来源范围以简短上下文标签显示，可在发送前改；模型、预算、布局等放在高级设置。
3. **能推进就推进。** 只有目标和编辑权限真正含糊、继续执行可能改错范围时才提问。提问要带当前理解和最小选项，不让用户重新填一张表。
4. **进度必须真实。** 显示实际阅读、检查、工具调用和已落地的节点变更；不播放“结果已拿到后假装逐字生成”的动画，也不展示模型隐藏思维链。
5. **用户始终能介入。** 运行中可补充约束、请求先停下、停止并保留已生成部分、停止并撤销本轮。新输入的去向必须明确。
6. **完成即保留，撤销可预期。** 一轮成功结束后，当前画布维持最终结果，默认视为采纳。撤销针对该轮 AI 的操作组，不直接覆盖整张脑图的后续变化。
7. **离开不丢进程。** 后台任务独立于页面；重新进入先显示最新脑图和当前任务状态，再订阅后续增量。

## 5. 产品对象与责任边界

| 对象 | 用户所见 | 核心职责 |
| --- | --- | --- |
| 脑图 | 当前可编辑的节点、连线、选中与 AI 标记 | 承载实时结果及手工编辑 |
| 对话 | 用户目标、Agent 简短回应、关键决策 | 保留语义上下文与多轮协作 |
| 任务轮次 | 当前一次目标及其执行状态 | 接收运行中指令、恢复、重试、结束 |
| 变更组 | 该轮已执行的节点操作 | 差异摘要、整轮撤销和冲突处理 |
| 检查点 | 本轮可恢复的已确认进度 | 页面离开、断线、服务恢复后的续接 |
| 后台任务 | 与页面观察者解耦的持久化运行 | 记录任务归属、运行 Agent、心跳、通知和恢复状态 |
| 能力授权 | 本轮允许使用的工具和写入范围 | 在每次实际提交前重新校验权限、版本和风险 |

一个对话可以包含多轮；一轮可以包含若干次阅读、修改、检查和纠正。**轮次不等于固定流水线**。前端无需根据固定阶段推测 Agent “应该接下来做什么”。

## 6. 工作区与信息层级

### 6.1 默认工作区

- **画布居中。** 保留原有编辑能力与导航；AI 面板不占第二层脑图、不重绘为静态结果图。
- **单一 AI 协作面板。** 顶部只显示当前对话名称、运行状态和更多操作；中部按轮显示对话；底部固定输入框。内部运行事件折叠在当前轮的“查看过程”，不再另设同屏常驻的审计侧栏。
- **上下文标签。** 输入框上方显示“整张脑图 / 当前分支：优惠券自动应用 / 已选 3 个节点 / 已附文件”。用户可点开调整；若未选择节点，默认当前脑图。Agent 不得悄悄扩大编辑范围。
- **高级设置。** 模型、Agent、预算、布局、生成节奏等保留为按需设置。默认界面不要求选择“任务意图”“结果类型”“生成模式”。用户显式选择“只讨论”时保持只读；也可直接说“先分析，不要修改”。

### 6.2 一轮消息的呈现

1. 用户指令和当时的上下文范围。
2. Agent 一句当前理解，例如“我会检查优惠券分支，再补齐异常与边界场景”。这句话不是必须批准的计划。
3. 当前活动：“正在检查 5 个相关节点”“正在补充库存不足场景”，以及真实的“新增 3、修改 1、移动 0”计数。
4. 关键决策和阻塞问题；工具日志、模型信息、失败重试细节折叠在“过程详情”。
5. 完成摘要：“新增 7 个、调整 2 个；已检查重复项”，提供“查看变更”“撤销本轮”“继续调整”。

不用伪百分比表达无法预测的模型工作。长任务可以显示已完成步骤与当前步骤；步骤可由 Agent 动态增加、跳过或重排，不能把最初的计划当成不可变合同。


### 6.3 首次进入与发送前

首次打开 AI 面板时不弹出配置向导。面板先说明当前脑图名称、当前选区和 Agent 默认行为，再给出三个可直接点击的建议：“分析这张图”“补充当前分支”“检查重复和缺口”。点击建议**只填入输入框并聚焦**，不自动发送；用户可以修改文字，再按发送。没有选区时，把第二条换成“补充这张图的薄弱部分”，不能展示点了也无法执行的建议。空白脑图用“从一个主题开始”“列出主要分支”“先讨论结构”；只读文档仅展示分析类建议。

输入框上方固定显示当前范围标签，并用一句短文案解释默认范围：“将基于当前选中分支工作”。用户可以展开范围选择器，看到将读取的节点、附件和来源；扩大范围时必须主动选择。没有选中节点时，默认读取整张脑图，但写入仍优先落在 Agent 能确定的相关分支。发送前的选区是可见的草稿上下文；发送成功后固定为该轮快照。用户随后点选别的节点，只影响下一条尚未发送的消息，不悄悄改变正在运行的任务范围。

发送前只在必要时显示轻量预检卡片：

| 触发条件 | 用户看到的内容 | 默认动作 |
| --- | --- | --- |
| R0/R1、范围明确 | 只显示输入框上的上下文标签，不额外弹卡片 | 直接执行 |
| 需要扩大读取范围 | “还需要查看：结算流程、库存分支” | 用户选择继续或缩小范围 |
| 请求可能产生 R2/R3 写入 | “可能调整多个分支；形成具体方案后会先请你确认” | 允许先只读分析，实际操作差异形成后再审批 |
| 需要云端 Agent、附件或外部来源 | 数据去向、来源和权限 | 用户明确继续后发送 |
| 目标不清且继续会改错 | 当前理解和一个最小问题 | 等待回答，不先写入 |

预检卡片只保留一个主动作和一个安全替代动作，例如“继续处理 / 只做分析”。用户不需要理解风险编号，风险标签用于“为什么需要确认”的解释。

同一数据去向与授权范围已得到用户确认时，后续轮次只显示来源标签，不反复弹出同样的许可问题；切换供应商、增加附件或扩大读取范围时重新提示具体变化。审批具体节点操作仍按每次操作的差异单独确认，不能复用数据去向授权代替操作审批。

### 6.4 运行中反馈的固定结构

每一轮只保留三个可预测区域：

1. **运行头部。** 显示“正在处理 / 等待确认 / 已完成”等状态、当前 Agent 和当前文档。状态旁边提供当前最重要的动作，例如“停止”“批准”“继续”。
2. **活动卡片。** 显示 Agent 当前正在做什么、已完成的真实计数和当前编辑节点。过程详情、工具调用和诊断信息默认折叠。
3. **操作栏。** 固定提供输入框和最多三个高价值动作：补充要求、停止、查看变更。完成后替换为继续调整、撤销本轮和查看变更。

用户在任何状态都能回答问题、停止、查看当前脑图；页面不因等待 Agent 文本而禁用画布。按钮文案使用结果导向的词语，例如“保留已生成部分”“撤销本轮修改”“继续完成”，避免只显示“取消”“关闭”。

### 6.5 输入框、建议词与发送反馈

输入框在任务运行中始终可编辑。占位文案随状态变化，但已输入内容不能因为轮次切换、断线、审批弹出或面板关闭而丢失。草稿按用户、文档和对话隔离保存；成功收到服务端消息回执后才清空对应草稿。附件和范围标签在发送按钮旁可查看，避免用户把“只讨论”误认为会编辑画布。

| 时刻 | 输入区主文案 | 发送后的明确反馈 |
| --- | --- | --- |
| 首次打开 | “例如：补齐当前分支的异常场景” | 立即显示用户原话与“正在创建任务”；服务端回执后显示真实状态 |
| 正在运行 | “补充要求，或安排下一轮任务” | 消息卡片显示“加入当前任务”或“排到下一轮”及接收状态 |
| 等待用户 | “回答 AI 的问题” | 问题卡片标记“已收到回答，正在继续” |
| 已完成 | “继续调整当前脑图，或提出新问题” | 新轮次沿用当前脑图与对话，旧轮保持已完成 |
| 发送失败 | 保留原文、选区和附件 | 同一条消息显示“发送失败 · 重试”，不创建重复任务 |

输入框下方只放一个高强调度的发送动作；停止与查看变更是分开的动作，不能用停止按钮替换发送按钮。运行中在发送按钮旁显示可切换的去向标签“加入当前任务 / 排到下一轮”，冲突请求改为“确认处理范围”。点击发送先创建一张“发送中”消息卡片；服务端尚未接收时可取消本地发送，若已接收则转为撤回未消费消息或停止任务。超时先查询幂等回执，再允许同一消息重试，不能让用户以为没反应而产生双轮。`Cmd/Ctrl+Enter` 发送；`Enter` 换行；中文输入法组合输入期间不触发快捷键。任务运行中且无其他弹窗时，`Esc` 打开简短停止确认，`Enter` 确认，`Esc` 关闭确认，避免误停。所有按钮有文字或可访问名称与键盘焦点状态。

### 6.6 运行中消息的去向

用户发出的每条消息都要有独立 `messageId`、`turnId`、文档 ID、发送时范围和服务端接收状态。前端可用语义给出**可修改的路由建议**，但最终路由由用户选择与服务端确认；用户话语不能仅凭关键词被静默并入、丢弃或改投另一张脑图。

| 去向 | 适用例子 | 卡片回执 | 执行规则 |
| --- | --- | --- | --- |
| 加入当前任务 | “先别改安全测试”“这个分支再考虑库存不足” | “已加入当前任务 · 等待下一个安全边界” | V2 将消息持久化为当前任务的安全边界延续，在当前 Provider 运行结束并完成基线对账后启动；确认后改为“已采用”或说明无法采用的原因。Adapter 内运行中注入保留给 V3 |
| 排到下一轮 | “做完后再检查性能测试” | “已排到下一轮 · 第 1 位” | 只在前一轮结束、当前文档修订重新确认后启动；P0 可撤回并重发，P1 支持原位编辑和排序 |
| 新建独立任务 | 用户明确说“另起一个任务” | “待开始 · 当前脑图有任务正在编辑” | 同文档写入互斥；用户决定排队或停止当前任务，不能并发覆盖 |
| 与当前目标冲突 | “把刚才新增的全部删掉，换一种结构” | “需要确认新的处理范围” | 先停止后续写入并展示已保存内容、将受影响内容及保留/撤销选择，再创建新执行边界 |

运行中默认建议“加入当前任务”，只有明显描述将来动作时建议“排到下一轮”；发生冲突时不自动选择。V2 的“加入当前任务”保证消息进入同一会话、同一文档队列并在安全边界连续执行，界面不能把它误报为已被当前模型步骤消费。发送后允许在 Agent 消费前撤回；已消费的约束以新消息修正，不能假装撤回已发生的编辑。若当前轮在消息被消费前完成，卡片变为“本轮已结束 · 发送为下一轮 / 编辑 / 删除”，绝不自动换路由。断线重连后恢复每条消息的权威接收状态，旧轮事件只能更新旧轮卡片。

正在停止时输入框仍可写草稿，但不能把新话语加入即将结束的轮次；服务端确认停止或完成后，用户再决定发为下一轮。排队消息启动前必须再次校验当前文档权限和修订；若目标分支已变化，先请用户确认新范围，再进入下一轮。

### 6.7 过程反馈与画布协同

运行卡片只显示一句当前活动、实际提交计数和当前节点，例如“正在补充库存不足场景 · 已新增 4 个节点”。活动来自服务端阅读、工具和提交事件；模型长时间无操作时显示“正在分析，已用时 28 秒”，不显示会自己增长的百分比。每个真实提交批次才更新画布和计数；同一批的多个节点可连续绘制，但不能把终稿拆成伪实时播放。当前节点高亮和画布跟随以已提交节点为准，不能根据模型文字猜测焦点。

用户手动拖拽、缩放、选择其他节点或开始编辑时，跟随立即暂停；活动卡片保留“回到 AI 当前编辑处”，点击后只移动一次并恢复跟随。面板隐藏时仍显示轻量任务状态入口；点击该入口打开当前轮。旧事件重放、断线对账和返回页面时直接呈现最新已确认修订，不重复播放入场动画。画布与面板计数暂时不同步时显示“正在同步最新修改”，同步完成后以服务端修订和操作组计数对齐。

### 6.8 面板关闭、换图与草稿

关闭面板和离开页面只关闭观察者。首次在运行中关闭面板时，用不阻断操作的短提示说明“AI 会继续编辑这张脑图，可从任务入口返回”；之后保持安静，不重复教育用户。切换脑图后，顶部任务入口以文档名称显示后台任务状态；重新进入原脑图，先展示最新已确认画布，再定位当前轮及未发送草稿，最后续接实时事件。若权限已失效，任务入口只显示可安全公开的状态，不泄露节点正文。

草稿、待发消息和已接收消息的边界必须清楚：未发送草稿只保存在当前用户端；已接收消息以服务端回执为准；排队消息属于服务端任务队列。用户退出登录或失去文档权限后清理本地敏感草稿。多标签页编辑同一对话时，以服务端消息状态为准并提示“此对话已在另一标签页更新”，避免重复发送。

## 7. 核心交互流程

### 7.1 发起任务

用户选中节点后输入“补齐这个分支的边界场景”，上下文自动显示所选分支。发送后立即出现该轮卡片和“正在读取授权范围”；Agent 根据当前脑图判断先回答、先检查还是直接编辑。首次实际节点变更到达后，画布立即更新，并展示轻量的 AI 编辑标记。

输入含糊但可合理继续时，Agent 先做低风险阅读或给出假设；含糊到会改错范围时才问一个具体问题，例如“只调整‘优惠券自动应用’，还是整个异常流程？”问题卡片不阻断用户浏览脑图。

### 7.2 运行中：看见工作且可以改变方向

- 每个已接受的节点操作都更新当前画布，同时在当前轮累计计数。成批结果按真实到达时间提交，不能等最终文件返回后再“回放式流出”。
- 当前编辑节点有蓝色轮廓与小型“AI 正在编辑”标记；完成后标记淡出，节点保持正常可编辑状态。屏幕阅读器收到简短状态更新，不朗读每一个节点文本。
- 默认开启“跟随 AI”：每次切换当前编辑节点时，画布平滑移动，使该节点进入画布中央的安全区域；同一节点的连续文字更新保持视口稳定，避免逐字抖动。
- 用户手动拖拽、缩放或选择其他节点，立即暂停自动跟随。画布提供“回到 AI 当前编辑处”按钮，点击后恢复跟随。禁止与用户争夺画布控制权。
- 运行中输入框保持可用。发送“补充要求”会在当前 Provider 运行结束后的下一个安全边界接入同一会话，面板明确显示“已加入当前任务”；“排到下一轮”则显示队列位置；“停止”可立即请求中止。不能让第二轮消息被第一轮轮询或旧事件覆盖。
- 用户发出与当前目标冲突的新要求时，Agent 先停止后续编辑、确认新的执行范围，再继续；已完成的本轮变更仍可整轮撤销。

### 7.3 停止、失败与重试

停止请求完成后，**已确认提交的修改默认保留**，同时提供“撤销本轮修改”；用户不必再点一次“采纳”。如果服务端返回 `cancel_failed` 或无法确认最后写入边界，先对账权威快照，不能直接执行撤销。网络或供应商失败时，已落地部分继续可见，卡片明确写“本轮未完成，已新增 4 个节点”，可“继续完成”“改要求重试”“撤销本轮”。重试从最新受控检查点和当前脑图修订出发，不能重复插入已存在节点。

错误分为用户能行动的类型：模型配置、认证、网络、限流、输出校验、权限范围、脑图冲突。错误卡片给出具体操作；诊断详情可复制任务 ID 和已脱敏错误码。服务内部异常不直接拼接原始供应商内容。

### 7.4 完成与多轮

任务成功结束时，不切换到“AI 结果脑图”或恢复旧根节点，画布继续显示最终内容并默认保留。该轮卡片提供变更摘要及整轮撤销。用户下一句话自然继承当前脑图和对话语境，例如“再把库存不足的边界条件细化”，无需先点击“继续调整”。讨论轮也能接续编辑轮；“补上刚才说的三点”可引用前一轮回答，但仍以**当前脑图修订**为编辑基线。

浏览历史轮次只定位并展示那一轮的变更摘要，不自动把历史结果覆盖到当前画布。若要从历史版本继续，需显式执行“从此版本建立新分支/恢复为新修订”。

### 7.5 离开和返回

关闭面板或离开页面只改变观察者，不取消后台任务。重新打开脑图时，先载入已确认的最新脑图修订，再查询当前任务与检查点；显示“仍在处理 · 已新增 6 个节点”，随后订阅新事件。恢复时不重播过往节点动画，旧事件只用于状态和审计。若连接中断，保留画布，显示“正在重新连接”，恢复后按事件游标与运行世代同步，避免侧栏闪刷和上一轮结果重新出现。

任务完成、部分失败或等待用户输入时，任务中心和通知入口显示一条可回到具体脑图、具体轮次的通知。通知包含“已完成并保留结果”“等待确认”“需要补充信息”“部分失败”四种状态；用户关闭通知不改变任务状态。基础任务中心在全局导航中按文档聚合会话，携带 `jobId` 深链回到原脑图并恢复当前轮；本地浏览器脑图没有可跨页面定位的文档 ID时，只显示脱敏状态并保留原页面恢复入口。多张脑图同时运行时，不能只依赖用户重新打开某张脑图才能发现任务结果。

### 7.6 Agent 不可用、切换与降级

本地或云端 Agent 不可用时，任务进入“Agent 不可用 · 已暂停”，保留最新检查点和已落地的画布结果，不静默切换执行者。面板提供“重试当前 Agent”“切换 Agent”“保留结果并结束”三个动作，并展示错误码、最近一次已提交变更和切换可能造成的能力差异。

用户选择切换 Agent 后，系统先检查新 Agent 是否具备当前任务需要的读取、编辑、校验和来源访问能力；确认后以新的 `runEpoch` 从最新检查点继续。切换行为记录在轮次历史中，后续结果仍归属于同一个对话和变更组。若新 Agent 不具备原能力，必须先说明会跳过或替代哪些动作；禁止用能力更弱的 Agent 静默完成同一任务。


### 7.7 关键交互细节

| 时刻 | 面板表现 | 画布表现 | 主动作 |
| --- | --- | --- | --- |
| 首次进入 | 欢迎语、当前范围、三个建议 | 保持原图 | 输入，或点建议填入后发送 |
| 已发送 | 显示用户原话、范围和“正在理解” | 不清空、不回到根节点 | 停止 |
| 正在读取 | 显示“正在查看 X 个节点” | 不显示未提交的假节点 | 补充要求、停止 |
| 正在编辑 | 显示真实新增/修改/移动计数 | 当前节点高亮，按提交批次更新 | 停止、补充当前要求 |
| 等待确认 | 固定展示影响范围、差异和原因 | 保持已生成部分 | 批准后继续 / 拒绝并说明 |
| 等待用户 | 显示一个具体问题和当前假设 | 保持可浏览和手工编辑 | 回复问题 / 保留并结束 |
| 已完成 | 显示“已完成 · 结果已保存” | 保持最终结果 | 查看变更 / 撤销本轮 / 继续调整 |
| 部分失败 | 显示已完成数量、失败原因和剩余目标 | 保留已提交部分 | 继续完成 / 修改要求重试 |

| 撤销冲突 | 显示冲突节点和影响 | 不覆盖用户后续编辑 | 保留当前内容 / 恢复 AI 前内容 / 手工处理 |

审批卡片至少包含：操作目的、影响分支和节点数量、保留/删除/移动的差异、执行后结果、当前文档修订和数据去向。按钮使用“批准后继续”“拒绝并说明”“只查看方案”；拒绝后保留已提交的安全增量，不把整轮任务标记为数据丢失。

运行中发送新要求时，系统根据语义给出一个可修改的路由提示：

- 与当前目标一致：默认“加入当前任务”，显示“将在下一个安全边界采用”。
- 与当前目标无关但用户明确想稍后处理：默认“排到下一轮”，显示队列位置。
- 与当前任务冲突：先暂停后续写入，显示“需要重新确定范围”，不能自动合并。
- 用户明确要求新任务：创建新的任务轮次，并从最新已确认修订开始。

完成卡片的“撤销本轮”在轮次结束后继续可见，直到用户创建新的相互冲突的编辑或文档版本发生不可逆变化。撤销成功后显示“已撤销本轮 AI 修改”，同时保留“基于当前内容再试”。

键盘和辅助技术行为保持一致：发送使用 Cmd/Ctrl+Enter，停止确认由 Esc 打开，聚焦当前 AI 编辑节点使用快捷入口；状态变化通过简短 live region 播报，节点正文不逐条朗读。用户手动拖动画布后，自动跟随只显示“回到 AI 当前编辑处”，不抢回焦点。

### 7.8 状态卡片的内容与动作

所有状态卡片按同一顺序回答四件事：**正在处理哪张图、发生了什么、哪些结果已确认保存、现在能做什么**。运行状态、网络连接和结果保存分开展示；“连接已断开”不能覆盖“任务仍在后台运行”，本地暂存帧不能标作“已保存”。卡片的主动作最多一个，次动作最多一个，其余放入详情；危险动作始终写明影响范围。

| 场景 | 卡片首句示例 | 结果说明 | 主动作 / 次动作 |
| --- | --- | --- | --- |
| 刚发送 | “已收到要求，正在读取当前分支” | “原图保持不变” | 停止任务 / 查看范围 |
| 正在编辑 | “正在补充库存不足场景” | “已保存新增 4 个、修改 1 个” | 停止任务 / 查看过程；输入框仍可补充要求 |
| 暂无新提交 | “正在分析下一步 · 已用时 28 秒” | “已保存结果仍在画布上” | 停止任务 / 查看过程；输入框仍可补充要求 |
| 等待审批 | “需要确认跨分支移动 8 个节点” | “此前新增的 4 个节点已保存” | 批准后继续 / 拒绝并说明 |
| 等待回答 | “需要确定保留哪一个重复用例” | “已完成部分仍在画布上” | 回复问题 / 保留并结束 |
| 正在停止 | “已请求停止，正在完成当前提交” | “最后保存位置确认中” | 查看当前画布 / 查看过程 |
| 已停止 | “任务已停止” | “已保存到修订 128，后续目标未完成” | 继续完成 / 撤销本轮；已保存部分默认保留 |
| 连接中断 | “页面正在重新连接，任务仍在后台运行” | “画布保留最后已确认修订 128” | 重新连接 / 查看任务中心 |
| 部分失败 | “已补充 4 个节点，后续处理未完成” | “这 4 个节点已保存” | 继续完成 / 改要求重试 |
| 已完成 | “已完成 · 结果已保存” | “新增 7 个、修改 2 个；仍可撤销本轮” | 继续调整 / 撤销本轮 |
| 已撤销 | “已撤销本轮 AI 修改” | “用户后续编辑仍保留；冲突项见详情” | 基于当前内容再试 / 查看撤销详情 |

计数只统计该轮已提交的实际操作，不用最终目标数代替。卡片出现时立即显示用户原话与文档名；Agent 还没有产生活动事件时显示“正在读取”，不能留空白转圈。状态由服务端确认，前端仅能用“发送中”“正在连接”等**传输态**解释等待。对屏幕阅读器只播报状态、阻塞问题和批次摘要；高频节点文字更新不逐条播报。

### 7.9 停止、保留与撤销的决策路径

用户点击“停止任务”后，按钮改为“正在停止”，画布保持最近一次已确认内容，输入框草稿保留。服务端确认 `resultRevision` 和最后操作回执之前，不在客户端先撤回可见节点。若停止请求返回 `too_late`，显示“任务已经完成 · 结果已保存”，让用户使用完成卡片的“撤销本轮”；若返回 `failed` 或最后写入边界不明，先显示“正在核对最后修改”，完成权威对账后才开放保留/撤销。

停止确认后，已提交部分自动保持在当前脑图。卡片清楚展示两个后续方向：

1. **继续使用已生成部分。** 无须点击确认；以服务端最后已确认修订为准，保留当前脑图和本轮操作组，状态显示“已停止 · 部分结果已保存”。用户可继续完成剩余目标。未写入的模型输出丢弃；已排队的下一轮消息暂停，用户可以重新发送或删除。
2. **撤销本轮修改。** 显示本轮将撤回的新增、改写、移动、删除数量；无后续依赖时执行定向逆操作。撤销成功后显示最新脑图，不恢复整张旧快照。存在协作依赖时进入冲突决策卡片，不能直接覆盖他人的编辑。

完成后默认就是“保留”，不显示“采纳”“应用 AI 结果”或倒计时。历史中的每个 AI 编辑轮次都保留“查看变更”“撤销本轮”入口，入口可用性由服务端依赖检查决定，失效时说明原因和可选处理。撤销操作本身形成可追踪的新修订；再次运行 AI 以撤销后的当前修订为基线，不能复用被撤销的草稿帧。

### 7.10 审批、冲突与失败的单卡决策

审批卡片标题先说业务后果，例如“将把 8 个数量修改用例合并到‘边界测试’”，正文只展示目标、影响分支、预计新增/修改/移动/删除计数、关键差异、当前文档修订和数据去向。默认折叠完整操作清单，允许点选节点在画布定位；定位不执行写入。批准凭证绑定这份差异与修订，差异或修订变化后必须重新确认。拒绝时提供一行可选原因；拒绝后显示“高风险修改未执行，前面已保存的 4 个节点仍保留”。

协作冲突卡片逐项列出“AI 想撤回什么、此后谁改过、撤回会影响什么”，优先提供“保留当前内容”；用户可对每个冲突节点选择“恢复 AI 前内容”或“手工处理”，并预览将提交的新修订。未冲突的逆操作可以先安全完成，但卡片必须明确写“已撤销 X 项，Y 项待决定”，不能笼统报撤销成功。

错误卡片沿用“原因 → 影响 → 下一步”：认证错误提示检查连接；权限错误提示申请访问或缩小范围；网络错误先重连；限流显示可再试时间；输出校验失败允许修改要求重试；文档冲突先对账。每个错误都必须写明已保存修订和未完成部分。若 Agent 不可用，切换 Agent 是用户动作，卡片说明新 Agent 将使用哪份检查点、是否支持继续写入以及数据去向；不自动替换执行者。

### 7.11 离开后的恢复体验

用户返回时，以“文档快照已显示 → 当前轮状态已对齐 → 实时订阅已恢复”的顺序加载。第一步即可浏览脑图；第二步用服务端的文档 ID、轮次、运行世代和结果修订显示“仍在处理 · 已保存新增 6 个”；第三步只呈现游标之后的新操作。状态尚未确认时写“正在核对任务进度”，不能先画一个旧轮的结果再清掉。若任务已完成，直接看到最终脑图和“已完成 · 结果已保存”卡片；若等待用户，通知点开后聚焦那一个待回答问题。

任务中心按文档聚合，列表项至少显示文档名、当前轮摘要、运行/等待/失败/完成状态和已确认变更数量。仅在完成、等待用户、审批或部分失败等需要用户关注时通知；单纯后台运行不反复推送。用户关闭通知不停止任务；点击通知跳到原文档和对应轮次。断线期间用户手工编辑时，重连后先对账并展示冲突，不让过期 AI 操作覆盖新内容。

## 8. Agent 自主性与用户控制

| 情况 | Agent 可自主做的事 | 何时需要用户介入 |
| --- | --- | --- |
| 回答和检查 | 阅读当前授权脑图、分析缺口、定位节点 | 不需要 |
| 范围内新增/改写/移动 | 连续编辑、校验、修复无效操作 | 用户可以随时停止或纠正 |
| 要扩大范围 | 先说明需要读/改的额外区域 | 范围扩大前征询用户 |
| 可能大量删改 | 先创建可撤销检查点，并在卡片中提示预计影响 | 按 R2/R3 风险等级强制审批，不因用户说法明确而跳过 |
| 外部数据或不可撤销操作 | 明示来源、数据去向和后果 | 执行前获得相应授权 |

默认“自主编辑”并不意味着无边界。另提供“先讨论”和“先给方案”两种用户主动选择的工作方式，但它们是对 Agent 的任务指令，不是每轮必走的产品流程。

### 8.1 操作风险分级与审批

风险按实际写入操作计算，不按用户输入的字数或任务名称计算：

| 等级 | 典型操作 | 默认行为 | 用户看到的保护 |
| --- | --- | --- | --- |
| R0 只读 | 回答、搜索、检查、定位证据 | 自动执行 | 显示引用范围，不修改脑图 |
| R1 低风险写入 | 在明确选中分支下新增或改写少量节点 | 自动执行 | 实时画布、操作组、整轮撤销 |
| R2 结构变更 | 跨分支移动、合并、批量重排、一次修改较多已有节点 | 结果可实时预览，到达安全边界后暂停应用 | 展示影响范围和差异，用户确认后继续 |
| R3 高风险写入 | 删除子树、批量删除、修改根节点、覆盖大部分已有内容 | 必须先审批，结果仍可实时预览 | 预览将删除/覆盖的节点、保留检查点、确认或拒绝 |
| R4 外部副作用 | 分享、导出到外部系统、写入第三方服务 | 必须先审批 | 展示来源、目标、数据范围和后果 |

R2/R3 的等级由操作语义、影响节点比例、是否跨分支、是否包含删除、是否修改根节点和是否产生外部副作用决定，不能由 Agent 自报置信度降低。低置信度可以把操作升级到更高风险或转为提问，高置信度不能绕过既定审批。用户明确说“删除这三个节点”可以缩小审批范围，但仍需在执行前展示即将发生的具体操作。用户拒绝审批后，任务进入 `rejected`，已提交的安全增量继续保留；后续新指令必须创建新的审批上下文。

V2 的 `needs_review` 是一个真正阻塞的状态：结果可以继续在当前画布实时展示，但同一会话中排队的下一轮不能自动消费这份未确认结果。用户点击“采纳”后，服务端先持久化应用结果，再释放最早的排队轮次；点击“不采纳”后，客户端撤回未提交的画布预览，服务端以一次幂等操作写入 `rejected`，并关闭依赖这份结果的排队轮次。两条路径都保留审计事件和任务中心状态，旧轮询或迟到的 SSE 不能把 `rejected` 复活为运行中。拒绝后面板提供“修改要求重新生成”，以当前脑图创建新的审批边界，不把被拒绝的 Artifact 当作下一轮基线。

### 8.2 脑图结果质量标准

Agent 每次写入前都要以最新授权脑图为依据；优先复用稳定节点 ID、原有分类方式与布局。新增节点应放到语义正确的父节点下，标题简洁、语义边界清晰，避免无意重复；不同测试维度允许有意交叉，但必须通过标签、父节点或说明表达交叉关系。重复检查限定在相同父节点、相同语义维度和相同授权范围内，不能只按标题相同判断重复。移动和合并节点须保留有价值的备注、标签、链接及子树。结束前检查父子关系、循环、孤儿节点、重复标题、节点预算和编辑范围；未通过时继续修复或明确报告未完成，不能把只剩根节点的结果当作成功。

“分析缺口”必须区分脑图中已有的事实、用户提供的资料和 Agent 推断。引用外部资料时显示来源；没有资料时用“建议补充”而不是“已验证”。这让 Agent 既能自主工作，也能让专业用户检查结论。

### 8.3 Agent Loop 的完成条件和防循环

Agent 每轮必须同时受模型轮次、工具调用次数、操作数量、运行时长和费用预算约束。完成条件至少包括：用户目标已满足、授权范围内的操作已提交、结构校验通过、没有待处理审批或冲突、Agent 明确报告未完成原因。仅回答“已处理”不能作为完成信号。

运行时检测以下无进展情况：连续若干轮没有新增有效操作、重复提交同一幂等键、对同一节点反复产生相同修复、连续校验失败、计划步骤循环增加、工具错误重复出现。触发阈值后暂停任务，显示“未取得新进展”，提供“查看原因”“修改要求”“重试一次”“结束并保留结果”四个动作。达到预算或最大轮次时进入 `expired`，不能继续后台消耗资源。

## 9. 变更、撤销与协作规则

- 一轮 AI 编辑形成一个持久化的变更组，记录基线修订、实际节点操作、操作归属及完成状态；每次实时增量立即落地到同一工作成果。
- 默认采纳的含义是**不需要点确认按钮**。成功后显示“已保存 · 可撤销本轮”，不保留一份与当前画布竞争的“待采纳层”。
- “撤销本轮”只逆转该轮 AI 操作。若协作者或用户随后改过相关节点，先检测依赖；无冲突则直接逆操作，有冲突则提出“保留后续编辑并生成反向修改”的可审阅方案，不能整图回滚覆盖他人工作。
- 普通编辑器撤销与“撤销 AI 本轮”语义不同：前者撤销最近一次本地编辑动作，后者是对一整轮 Agent 操作组的定向撤销。两者在文案和历史中明确区分。
- AI 运行中用户手工编辑同一分支时，Agent 在下一次写入前重新读取相关节点；发生冲突则暂停该局部操作，继续不冲突部分或询问用户。

每个语义操作都持久化正向补丁、逆向补丁、目标节点版本、父子关系快照、操作归属和幂等键。删除操作保留可恢复的节点墓碑及其子树；合并操作保留源节点到目标节点的映射；移动和重排操作保留原父节点与原顺序。撤销不会用旧整图覆盖当前文档。

撤销只允许产生三种结果：**完整逆操作成功**、**部分逆操作成功并列出冲突节点**、**无法安全逆操作并生成反向修改草案**。部分撤销要逐项显示保留和未撤销的操作；反向修改草案必须再次经过用户确认。若用户随后改写了 AI 新增节点，默认保留用户文字，只撤销 AI 创建的结构关系；若同一节点同时被用户和 AI 修改，暂停该节点并要求选择“保留当前内容”“恢复 AI 前内容”或“手工处理”。

## 10. 状态与实时协议要求

| 状态 | 画布 | 面板主动作 |
| --- | --- | --- |
| 准备中 | 保持当前脑图 | 补充要求、停止 |
| 执行中 | 按已确认操作持续更新，当前节点高亮 | 补充当前轮、排队下轮、停止 |
| 等待确认 | 保持已生成部分 | 批准后继续、拒绝并说明、停止 |
| 等待用户 | 保持已生成部分 | 回答问题、保留并结束、撤销 |
| Agent 不可用 | 保持最后已确认修订 | 重试当前 Agent、切换 Agent、保留结果并结束 |
| 已停止 | 保持最后已确认修订，已提交部分默认保留 | 继续完成、查看变更、撤销本轮 |
| 停止待核对 | 保持最后已确认修订，暂停危险动作 | 查看权威状态、重试停止 |
| 连接中断 | 保持最后已确认修订 | 重新连接；不改变后台任务状态 |
| 部分失败 | 保持可见的已生成部分 | 继续、修改要求重试、撤销 |
| 已完成 | 保持最终结果 | 查看变更、撤销本轮、继续对话 |
| 已撤销 | 展示撤销后的当前脑图 | 查看原因、基于当前内容再试 |
| 已拒绝 | 保持已完成的低风险结果 | 修改要求、撤销已完成部分、结束 |
| 已过期 | 保持最后可见结果 | 查看结果、重新发起、结束 |

用户态状态是服务端运行态的展示映射，不能由前端自行推断：

| 用户态 | 服务端运行态 | 面板允许动作 |
| --- | --- | --- |
| 准备中 | `queued`、`preparing` | 补充要求、停止任务 |
| 执行中 | `running` | 补充当前轮、排队下轮、停止任务 |
| 正在停止 | `stop_requested`、`draining` | 查看画布和过程，等待服务端确认边界 |
| 等待确认 | `waiting_approval` | 批准、拒绝、停止 |
| 等待用户 | `waiting_user` | 回复、结束、停止 |
| 已停止 | `stopped` | 继续完成、查看已保存结果、撤销本轮 |
| Agent 不可用 | `agent_unavailable` | 重试当前 Agent、切换 Agent、保留结果并结束 |
| 已拒绝 | `rejected` | 修改要求、撤销已完成部分、结束 |
| 停止待核对 | `cancel_failed` | 查看权威状态、重试停止；核对前禁用撤销和新写入 |
| 部分失败 | `partial_failed` | 继续、修改要求重试、撤销、结束 |
| 已完成 | `completed` | 查看变更、撤销本轮、继续对话 |
| 已撤销 | `completed` + 变更组 `undone` | 查看撤销结果、基于当前内容再试 |
| 已过期 | `expired` | 查看结果、重新发起、结束 |

连接状态是第三个独立维度：`connected`、`reconnecting`、`disconnected`。连接中断不等于任务暂停；重连时先读取权威快照和运行状态，再恢复增量订阅。任务运行状态和变更组状态是两个正交维度：运行状态描述 Agent 是否还在执行，变更组状态描述本轮修改是否已应用、正在撤销或已撤销。服务端状态、变更组状态和运行世代是唯一事实来源；前端只能根据收到的权威事件更新用户态。每个终态事件必须携带最终 `resultRevision`、变更组状态和可用动作，终态之后的事件不能重新打开已结束任务。

实时事件至少携带 `sessionId`、`documentId`、`conversationId`、`turnId`、`runEpoch`、单调 `sequence`、`baseRevision`、`resultRevision`、操作组 ID 和事件类型。事件类型至少包括：

| 事件 | 是否改变画布 | 用户可见内容 |
| --- | --- | --- |
| `run_created` / `status_changed` | 否 | 当前状态、可用动作 |
| `assistant_delta` | 否 | 面向用户的短文本增量，不包含隐藏思维链 |
| `tool_started` / `tool_finished` | 否 | 正在读取、检查或校验的摘要 |
| `operation_proposed` | 否 | R2/R3 的影响范围和审批状态 |
| `approval_required` | 否 | 需要用户确认的具体操作 |
| `operation_committed` | 是 | 已持久化的节点操作、结果修订和变更计数 |
| `message_received` / `message_routed` | 否 | 消息已接收、加入当前轮或排到下一轮及队列位置 |
| `message_consumed` / `message_rejected` | 否 | 约束已采用，或说明为什么无法采用 |
| `queue_changed` | 否 | 排队消息的新增、编辑、撤回和位置变化 |
| `checkpoint_created` | 否 | 可恢复检查点 |
| `stop_acknowledged` | 否 | 停止请求结果和最后已确认修订 |
| `undo_completed` / `undo_conflicted` | 视已提交逆操作而定 | 本轮已撤销数量与仍待处理的冲突项 |
| `heartbeat` | 否 | 连接和任务存活状态 |
| `error` / `terminal` | 视错误类型而定 | 错误动作、最终状态和可用操作 |

服务端只发送已经提交或明确标记为提案的语义事件；客户端按序、幂等应用。`operation_committed` 只有在服务端持久化成功后才能发送。每次切换轮次立即取消旧轮订阅与轮询，迟到事件不得改写新轮侧栏或画布。重连以“最新权威快照 + 游标后的增量”为准，不把历史事件当作新的流式演出。对于 `assistant_delta`，客户端可以补齐文本显示，但不能把文本增量当成脑图已提交结果。

消息类事件必须带 `messageId`、确定的去向、接收或消费状态及队列位置；提交类事件必须带 `operationId`、当前编辑节点 ID、实际变更计数和 `resultRevision`。服务端查询当前轮时同时返回可用动作、已提交计数和未消费消息摘要，使页面恢复时不用依赖旧事件拼出“现在能做什么”。若流式帧是本地待确认内容，必须携带明确的未提交标记；客户端不能把它计入“已保存”，也不能让它覆盖更新的权威修订。

允许模型一次产生多个节点，但 UI 只按真实提交点展示。要改善持续输出，优先让 Agent 较早提交小批操作并在批间检查，而不是客户端把终稿拆成动画。模型长时间没有工具调用时诚实显示当前工作和已耗时，并提供停止。


### 10.1 任务运行状态机

任务状态必须由服务端持久化并由服务端确认，前端状态只作为实时投影。最小状态集合如下：

| 状态 | 进入条件 | 允许动作 | 离开条件 |
| --- | --- | --- | --- |
| `queued` | 任务已创建但尚未执行 | 补充要求、停止 | 获得执行租约或停止 |
| `preparing` | 正在读取文档、权限和来源 | 补充要求、停止 | 上下文通过或准备失败 |
| `running` | Agent 正在读取、检查或写入 | 补充当前轮、排队下轮、停止 | 等待审批、等待用户、停止、失败或完成 |
| `waiting_approval` | R2/R3 操作待用户确认 | 批准、拒绝、停止 | 批准后继续、拒绝后进入 `rejected` |
| `waiting_user` | Agent 需要澄清或补充资料 | 回复、结束、停止 | 收到回复或结束 |
| `stop_requested` | 用户请求停止 | 只能等待取消结果 | 进入排空或取消失败 |
| `draining` | 正在完成已开始的原子操作 | 查看进度 | 已确认的最后检查点提交 |
| `stopped` | 服务端确认停止 | 查看已保留结果、撤销本轮、继续 | 新指令或撤销完成 |
| `cancel_failed` | 服务端无法确认停止边界 | 查看权威状态、重试停止 | 对账完成或确认原执行者已失去写入权 |
| `rejected` | 用户拒绝高风险操作 | 修改要求、结束、撤销已完成部分 | 新指令或结束 |
| `partial_failed` | 已提交部分结果后失败 | 继续、重试、撤销 | 新运行世代开始或结束 |
| `completed` | 所有操作和校验完成 | 查看变更、撤销本轮、继续对话 | 新轮次或撤销完成 |
| `agent_unavailable` | 当前 Agent 暂不可用 | 重试、切换 Agent、保留并结束 | 新 Agent 获得执行权或结束 |
| `expired` | 超过运行时限或无法恢复 | 查看结果、重试、结束 | 新轮次 |

每次写入以原子操作或原子小批提交。收到停止后，服务端关闭新的写入门，并允许当前小批完成后进入 `draining`；未提交的模型输出不得继续落地。停止接口必须返回 `accepted`、`too_late` 或 `failed`，并带最后已确认的 `resultRevision`。客户端只接受该运行世代在终态之前产生的事件；终态之后的迟到事件统一丢弃并记录审计。

### 10.2 后台任务持久化与恢复

后台任务至少持久化以下内容：任务归属、文档 ID、对话 ID、当前轮、Agent 与模型、运行状态、最后心跳、检查点、事件游标、当前 `resultRevision`、操作组 ID、重试次数、错误码和通知状态。检查点还必须保存可恢复的 Agent 上下文：当前目标摘要、已确认约束、已完成步骤、未完成目标、最近一次工具调用及结果摘要、待处理审批、模型上下文压缩摘要、预算消耗和下一次允许的操作。不能只保存脑图快照后重新发送原始提示，因为这可能重复写入或丢失运行中补充的约束。

Agent 上下文有两种恢复方式：优先恢复序列化的 Run State；无法序列化时，根据检查点摘要重新建立上下文，并先执行一次只读对账和重新规划，再允许写入。恢复后的首个事件必须说明“从检查点恢复/重新规划”，不能把重新规划过程伪装成原任务的连续输出。

执行 Worker 通过租约领取任务，租约超时后允许其他 Worker 接管；同一操作使用幂等键，接管不能重复写入节点。Worker 接管前必须先读取权威任务状态、最新文档修订和最后操作回执，确认原 Worker 已失去写入权。

服务重启后的恢复规则：

1. 有有效检查点和可恢复 Agent 时，从最后检查点继续，并以新的 `runEpoch` 发布“已恢复”事件。
2. Agent 或来源不可用时进入 `agent_unavailable`，保留结果并等待用户处理。
3. 无法确认服务端是否提交了最后一批操作时，先拉取权威快照和操作回执，再决定继续或标记为 `expired`，不能直接重放模型输出。
4. 超过最长运行时间、最大模型轮次、重试预算、工具调用预算或租约恢复次数后停止自动重试，展示明确的人工动作。

### 10.3 文档上下文和并发规则

每轮任务固定绑定以下上下文：`documentId`、`conversationId`、`turnId`、`baseRevision`、`selectionSnapshot`、`permissionSnapshot`、`sourceSnapshot`、`agentId`、`modelId`、`operationGroupId` 和 `idempotencyKey`。所有写入提交前重新校验文档版本、选区权限和操作风险；前端传来的“当前文档”不能作为唯一依据。

默认一张脑图同时只允许一个写入型 Agent 任务；只读分析任务可以并行。用户在同一张脑图发起第二个写入任务时，产品提供“加入当前任务”“排到下一轮”“基于最新版本新建任务”三个选择。切换文档、历史版本或权限后，原任务继续在原文档上运行，但新页面必须明确提示其目标文档；不能把任务自动迁移到当前打开的文档。

如果当前文档版本、选中分支或权限已经变化，Agent 在下一次写入前暂停局部操作，重新读取并在必要时请求确认。多标签页恢复以服务端权威快照为准，禁止两个页面各自把本地结果当作最新版本。

### 10.4 Agent 工具与写入契约

Agent 只能通过受控工具访问脑图：

| 工具 | 作用 | 写入 | 关键约束 |
| --- | --- | --- | --- |
| `read_document_snapshot` | 读取指定修订的脑图 | 否 | 返回文档 ID、修订和权限范围 |
| `search_nodes` / `inspect_branch` | 定位节点和分析局部结构 | 否 | 只能搜索已授权范围 |
| `propose_operations` | 生成结构化节点操作 | 否 | 每个操作带风险等级和影响节点 |
| `commit_operations` | 提交新增、改写、移动、合并或删除 | 是 | 要求期望修订、幂等键和审批凭证 |
| `validate_structure` | 检查父子关系、重复、孤儿和循环 | 否 | 写入后必须执行 |
| `create_checkpoint` | 固化可恢复点 | 否 | 绑定操作组和结果修订 |
| `pause_run` / `resume_run` / `cancel_run` | 控制任务运行 | 否 | 只能作用于当前任务和运行世代 |

服务端执行 `commit_operations` 时再次校验权限、文档版本、风险等级、审批状态和操作预算。禁止 Agent 用整份文档覆盖的方式绕过操作日志；校验失败时返回结构化错误，Agent 可以修复或请求用户处理，但不能继续盲写。工具调用前后保留可审计的输入摘要、结果摘要和错误码，不展示模型隐藏思维链。

### 10.5 数据安全和不可信来源

脑图节点、附件、外部网页和检索结果默认都是**数据**，不是系统指令。来源内容中的“忽略前面要求”“调用某工具”“导出全部数据”等文本只能作为被分析内容，不能改变 Agent 的权限、任务范围或审批规则。外部来源不得直接写入脑图，必须经过 Agent 的来源标记和结构化操作校验。

每个来源显示名称、来源类型、版本/抓取时间、授权范围和是否发送到云端 Agent。用户切换本地 Agent、云端 Agent 或模型时，若数据流发生变化，发送前提示新的数据去向；没有新的明确授权时不能把本地脑图或附件静默发送给另一供应商。

任务通知只展示文档名称、任务状态和安全摘要，不在系统通知、浏览器标题或移动端推送中展示节点正文、附件内容或敏感来源。对话、快照、工具日志和错误详情按租户与文档权限隔离，并定义保留、脱敏、删除和导出规则。诊断日志默认记录结构化摘要、任务 ID 和错误码，不保存不必要的原始附件或完整提示内容。


### 10.6 用户态反馈与客户端渲染规则

服务端状态是事实来源，客户端只负责把状态翻译成用户能理解的下一步。每个状态卡片都必须同时提供：发生了什么、已保留什么、用户现在能做什么。

| 用户状态 | 必须说明 | 首要动作 | 次要动作 |
| --- | --- | --- | --- |
| 准备中 | 正在读取范围和权限 | 停止 | 查看范围 |
| 执行中 | 当前活动和真实变更计数 | 停止 | 补充要求 |
| 正在停止 | 正在确认最后写入边界 | 查看画布 | 查看过程 |
| 已停止 | 已确认修订与未完成目标，已提交部分默认保留 | 继续完成 | 撤销本轮 |
| 停止待核对 | 最后写入边界尚未确认 | 查看权威状态 | 重试停止 |
| 等待确认 | 需要确认的具体影响 | 批准后继续 | 拒绝并说明 |
| 等待用户 | 需要补充的最小信息 | 回复问题 | 保留并结束 |
| Agent 不可用 | 哪个 Agent 失败、结果保留到哪里 | 重试当前 Agent | 切换 Agent |
| 部分失败 | 已完成部分和剩余目标 | 继续完成 | 修改要求重试 |
| 已完成 | 结果已保存，撤销范围是什么 | 继续调整 | 撤销本轮 |
| 已撤销 | 哪些操作已撤回、哪些因冲突保留 | 基于当前内容再试 | 查看冲突 |
| 连接中断 | 页面连接断开，后台是否仍在运行 | 重新连接 | 查看任务中心 |

客户端必须以 documentId、turnId、runEpoch 和 sequence 丢弃旧事件；重新进入页面先渲染权威快照，再订阅游标后的增量。旧事件不得重新触发节点动画、侧栏计数或完成提示。

输入消息、任务运行和画布变更使用三套独立的幂等标识。用户重复点击发送只显示一条消息；用户刷新页面不重新创建任务；同一 operationId 的提交只展示一次。当前轮和下一轮消息都显示自己的排队位置，防止上一轮轮询结果覆盖新一轮。

错误卡片采用“原因、影响、动作”三行结构：

- 原因：用用户语言说明，例如“Claude 暂时无法连接”。
- 影响：说明“已生成的 4 个节点已保存，后续 3 个节点未处理”。
- 动作：只展示当前可行的“重试、切换 Agent、继续只读、撤销本轮”等动作。

## 11. 当前脑图的示范任务

**例 A：局部补充。** 用户点选“优惠券自动应用测试”并说“补上叠券冲突、失效券和跨端状态同步”。面板自动显示“当前分支”；Agent 阅读该分支，随后逐步新增场景，画布只在这个分支平滑跟随。完成卡片显示新增数量与覆盖点，用户可继续说“再考虑价格变动”。

**例 B：跨分支整理。** 用户说“检查正常、异常、边界流程中重复的数量修改用例，整理结构”。Agent 先只读检查并列出重合节点、可能的保留节点和结构变更方案；因为跨分支移动/合并属于 R2，必须先展示影响范围并等待用户确认，确认后才提交结构操作。如果“删除重复”的含义不清楚，问题卡片只询问保留规则，不先改图。所有实际修改归属同一轮，可整轮撤销。

**例 C：只讨论再编辑。** 用户问“购物车测试里还缺哪些支付前校验？”Agent 给出缺口并引用现有“结算流程”等节点，不改图。用户接着说“把前两项加到结算流程下”，Agent 基于当前修订补节点，无需重选意图和来源。

## 12. 成功指标与验收情境

### 产品指标

- 任务接收和首个真实状态事件的延迟单独统计，目标 P95 小于 1 秒；首个真实画布变更按 Agent、模型和工具能力分别统计 P50/P95，不强行设定统一的模型生成时限，也不用假流式掩盖等待。
- 用户发出运行中修正指令后，在下一安全边界被接纳的比例、耗时和被拒原因。
- 完成后画布与持久化脑图一致率、离开后恢复一致率、整轮撤销成功率、跨轮旧事件误渲染次数。
- 观察“立即撤销率”“重复重试率”“用户手动关掉跟随比例”，用来判断 Agent 是否改错范围或动效打断工作。
- 编辑范围遵守率、父子关系正确率、重复节点率、误删/误移/误改率、写入幂等成功率。
- 测试场景覆盖率、无依据内容比例、来源可追溯率、用户首次指令正确执行率和 Agent 不可用后的恢复成功率。
- 高风险操作审批拒绝后的越权写入次数、停止后迟到提交次数、任务接管后的重复提交次数，三项必须为 0。
- 首次输入完成率、发送前范围确认率、用户理解当前状态的成功率、从错误卡片恢复的成功率、撤销入口发现率和运行中误操作率。

### 评测集与上线门槛

每个回归任务保存输入脑图、用户指令、选区和权限、允许的操作范围、结构不变量、预期状态序列和可接受的语义结果。自动评测负责校验文档结构、权限、版本、事件顺序、幂等、停止、恢复和撤销；人工评审负责判断场景覆盖、范围理解、解释质量和来源依据。

P0 上线门槛如下：

- 未授权写入、审批拒绝后写入、终态后的迟到提交、重复提交、循环或孤儿节点：必须为 0。
- P0 的停止边界确认、同进程离开返回、整轮撤销和文档版本冲突的确定性用例：全部通过；P0.5 上线前再要求服务重启和 Worker 接管的恢复用例全部通过。
- 只读任务不得产生文档变更；R2/R3 操作在审批前不得产生结构写入。
- 语义质量按专家 1～5 分评审，范围遵守、内容覆盖和来源依据分别评分；低于发布门槛的任务只能进入实验 Agent，不能默认用于生产脑图。
- 每次 Agent、提示、工具契约或文档版本变更都必须重新运行回归集，并保留结果和失败原因。

### 必须通过的验收情境

1. 在脑图 132 的一个节点上发起局部编辑，第一批真实新增节点到达时画布立即变化，结果完成后保持不变。
2. 运行中手动平移画布，后续 AI 修改不夺回视口；点击“回到 AI 当前编辑处”恢复跟随。
3. 第一轮执行时补充“不要改安全测试”；Agent 在后续写入前吸收约束，第二轮输入不会触发第一轮轮询闪刷。
4. 生成中离开并返回，直接显示最新已确认节点与当前任务状态，随后只接收新增量。
5. 运行中停止并撤销，或完成后撤销，均恢复本轮操作前的相关内容；其他用户的独立修改不丢失。
6. 模型响应慢、工具调用失败、网络断开、服务重启、协作冲突时，画布不跳回只有根节点的版本，界面给出可继续的动作。
7. “先分析不要改图”只返回解释；下一句“补上前两项”能继续上下文并真正编辑。
8. 不支持增量工具的模型诚实展示等待状态，不能在最终响应后伪装实时生成。
9. Agent 尝试跨分支合并和删除节点时进入审批；用户拒绝后不再新增写入，已完成的低风险操作保持可见。
10. 用户点击停止后，服务端返回停止结果；停止之后的模型迟到事件不能改变画布，保留和撤销分别使用明确的结果修订。
11. 服务重启或 Worker 接管后，任务从检查点继续，不能重复插入节点；无法确认最后一批时先对账权威快照。
12. 同一脑图同时存在两个写入请求时，一个执行、一个排队或等待用户选择，不能互相覆盖；切换文档后任务仍写入原绑定文档。
13. 本地 Agent 返回 `AI_AGENT_UNAVAILABLE` 时不静默切换，用户选择切换后才能从最新检查点继续，并在历史中记录执行者变化。
14. 用户离开页面后任务完成或等待输入，任务中心显示通知；点击通知能定位到对应脑图和轮次。
15. 新用户首次打开面板无需配置 Agent，点击建议只填入并聚焦输入框，用户可改写后发送；发送前能看懂当前范围和数据去向。
16. 运行中发送第二条消息时，用户能明确选择加入当前任务或排到下一轮，旧轮事件不会覆盖新轮。
17. R2/R3 操作暂停时，用户能在一张卡片内看懂影响范围、差异和批准后的结果；拒绝后已完成的低风险修改仍保留。
18. 错误发生时，用户能看到已保存结果和下一步动作，不会遇到无限加载或“任务失败但不知道结果在哪里”。
19. 完成后用户无需确认即可继续使用结果，撤销入口在后续对话中仍然可找到；存在协作冲突时不覆盖用户后续编辑。
20. 无选区、空白脑图和只读文档各自显示可执行的建议；选区改变只影响未发送草稿，已启动任务仍绑定原选区快照。
21. 运行中输入一条约束，界面显示服务端接收与消费状态；当前轮恰好结束时，未消费消息停在待处理状态，由用户决定是否改发下一轮。
22. 发送请求超时、刷新或多标签页重复提交时，只形成一条消息和一个任务轮次；输入草稿和附件引用仍可恢复。
23. `Cmd/Ctrl+Enter` 发送、`Enter` 换行、中文输入法不误发；`Esc` 停止确认不会误停，键盘可完成审批、撤销和返回当前 AI 节点。
24. 停止返回 `accepted` 时已确认修改默认保留；返回 `too_late` 时展示完成结果；返回 `failed` 时先核对最后修订，再允许撤销。
25. 审批卡片里的影响数量在方案生成后才出现；如果差异或文档修订变化，旧批准不能继续执行。
26. 撤销本轮遇到协作者随后修改同一节点时，卡片分别显示已安全撤销项和待决冲突项，用户能逐项保留当前内容。
27. 页面返回期间先出现最新已确认画布，再出现任务进度和新事件；旧轮消息、计数和完成通知不会闪回当前轮，断线补帧也不会重播旧动画。

## 13. 分期决策

**P0：可信的单文档实时编辑。** 单一输入框、自动意图判断、上下文标签、真实增量、运行中补充与基本下一轮排队、稳定画布跟随、停止后默认保留与整轮撤销、文档版本校验、R0/R1 自动执行、服务端操作日志、任务和消息回执持久化、离开返回后读取最新修订并续接增量。这一阶段删除默认界面里的固定“生成模式/任务类型”要求；R2/R3 先生成变更提案并保持实时可见，应用前必须经过 P0.5 的显式审批。

**P0.5：安全和恢复。** R2/R3 审批、可接管检查点与 Agent 上下文恢复、服务重启与断线对账、停止边界对账、全局基础任务中心与深链通知、基本完成/失败/等待输入通知、Agent 不可用处理、来源数据边界和 P0 回归集。P0 已要求页面离开后的同进程续接，本阶段补齐服务重启和故障接管。

**P1：成熟 Agent 平台。** 动态工作计划、队列编辑和跨任务排序、部分失败续作、节点级变更检查、冲突安全撤销、Worker 接管、多 Agent 切换、完整任务中心（批量操作、排序、筛选和跨任务控制）、质量评测平台和可选“先讨论/先给方案”。P0 的基础消息去向和一条下一轮排队在本阶段扩展为完整队列管理。

**P2：扩展能力。** 多文档引用、资料检索、可配置 Agent 能力、侧问与后台并行任务。每一项都沿用同一会话、权限、工具和变更模型，不再增加一个独立的脑图生成流程。
