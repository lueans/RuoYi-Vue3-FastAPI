状态：2026-09-27 用户确认“直接实施”后，已完成第 4 节前端最小范围并通过本地验证；第 5 节服务端原子队列接力未实施。

## 1. 本轮证实的缺口

生产 `MindmapAiDialog.vue::requestAgentSwitch` 的确认框仅展示目标名称和“已生成的脑图结果按当前预览状态保留”。本轮在使用该生产函数的隔离页面捕获了确认框与 Esc 取消结果：取消未调用停止、未改 Agent、未丢输入。新界面的信息要求尚未兑现：

1. 当前与目标 Agent/设备没有在决策点并列展示，平台与用户电脑之间的数据流向变化不明确。
2. 云端已提交、仅预览、待人工采纳、保存未确认是不同结果，不能合称“保留”。
3. 最新未完成 Todo 与已经发送的排队请求不可见，未发送草稿也未明确区分。
4. 已有队列不是自动迁移：后端取消可能关闭队列；保留结果或任务已完成的竞态可能释放队列。前端发现后继任务接管后拒绝切换，是安全措施，不是完成接力。

## 2. 如何参考 OpenDesign

- `apps/web/src/components/chat/PlanPill.tsx`：以最新计划摘要为入口，完整步骤按需展开；运行状态与步骤完成状态分开。这里沿用紧凑摘要，不把每次计划快照堆进弹窗。
- `apps/daemon/src/agent-session-resume.ts::resolveAgentResumePromptPolicy`：只有能证明原生会话可恢复时才省略转录；否则重新提供可见上下文。不能将供应商 session ID 当作跨 Agent 的接力合同。
- 原工程的本地项目文件与本平台的云端脑图提交模型不同。借用信息组织与状态分离，不复制其文件权限或把工具成功等同于脑图已保存。

## 3. 确认弹窗的信息设计

沿用 Element Plus、现有字体、颜色与按钮风格，不重做聊天工作台。标题为“停止当前轮并切换 Agent”，信息按以下顺序组织：

| 区域 | 展示内容 | 事实来源及边界 |
| --- | --- | --- |
| 当前 → 下一轮 | Agent 名称、平台运行主机/明确设备名 | 当前取绑定的 `job.agentKey/deviceId`，不能取可能正在编辑的表单；目标取本次选择与最新目录。 |
| 执行与数据 | 授权范围；执行地点是否改变；本机执行仍可能把授权上下文发给模型服务 | 不声称“本机执行就是离线”；不展示登录令牌、路径、供应商会话 ID；范围未知时标待确认。 |
| 脑图结果 | 已确认提交 / 仅预览 / 待采纳 / 状态待确认；停止不等于撤销 | 复用结果状态投影与真实回执。统计缺失显示未知，不补零；不得把旧版按操作累计的数字标为净变更节点数。 |
| 剩余 Todo | 最新清单未完成数量、当前项；可展开详情 | 只投影当前 job 的事件。没有 Todo 事件显示“未提供计划”，明确空清单才可显示无待办；Agent 自报不等于平台验收。 |
| 已发送队列 | 本会话可确认的排队请求数量、摘要、绑定 Agent，以及原队列规则说明 | 只计算服务端确认的任务，分页未完整/加载失败显示“状态未确认”，不把输入框内容计入队列。 |
| 未发送输入 | “输入内容保留；切换不会自动发送” | 保留既有草稿作用域与版本回执，不能为切换重写或消费草稿。 |

底部动作：“继续当前 Agent”与“停止并切换”。关闭/Esc 等同取消确认，不调用停止。确认后依次显示“等待旧 Agent 退出”“同步脑图结果”“下一轮已选择目标 Agent”；最后一步不能写成“新 Agent 已开始工作”。

如果未获得服务端队列迁移合同，只能解释原队列事实，不能显示“剩余任务已转交”。停止过程中后继任务接管时，应明确说明切换未生效并保留该任务，不静默改绑或再取消它。

## 4. 最小实施范围与安全条件

已新增只读 `mindmap-agent-handoff.js` 投影和 `MindmapAgentHandoffSummary.vue` 展示组件，由现有 `requestAgentSwitch` 的确认框承载；没有另建任务控制器，沿用现有 Element Plus 样式。

投影输入必须按 owner/session/job/epoch 归属过滤。正文按 Vue 文本渲染，不启用原始 HTML。长设备名、Todo 和请求摘要限长并允许换行，完整详情按需展开；不把公开对话以外的推理或原始工具输出插入确认框。

保留当前安全顺序：

1. 获取本次选择，校验目标及当前任务身份；展示摘要。
2. 确认后复核身份、目标状态和最新设备目录；任何变化不得误停另一任务。
3. 发一次原有停止请求；收到取消受理不是已经退出。
4. 等待执行退出回执，再等待原有画布 finalizer 成功。
5. 再次校验目标及任务归属；仅更新下一轮执行设置，不创建新任务。

摘要所描述的任务、目标或队列若在确认期间改变，不能继续使用旧确认。仅统计增长可以更新展示；影响行动后果的变化应结束本次确认，让用户重新选择。不能在 UI 中加入无后端支持的“迁移队列”开关。

新增确认信息不修改流式播放器、镜头、草稿 ACK、提交修订、幂等或撤销逻辑。把聊天信息投影作为只读层，不让弹窗成为脑图写入者。

## 5. 真正的排队接力仍需独立完成

成熟跨 Agent 接力需要服务端在同一授权与幂等边界下冻结待执行队列、记录用户选择、等待旧 epoch 退出与脑图修订确认，再创建新 run。用户选择的保留/取消/迁移行为必须有明确回执；默认不静默迁移、不扩大权限。

这项工作不能用“先改表单，再循环调用取消接口”替代：队列可能同时被释放，且逐项失败会产生不完整交接。实施前需确定队列处理产品选择，并补事务/崩溃恢复/重试合同。当前仅完成确认信息与前端防护，不把它标记为原工作台方案第 3 阶段全部完成。

## 6. 验收清单

- 当前平台 → 本机、本机 → 平台、同 Agent 换电脑，名称与位置准确；旧任务绑定不变。
- 直写回执、普通预览、保存失败、未知统计、纯讨论分别显示正确结果，不承诺未确认保存。
- Todo 缺失、明确清空、重排、旧 job 事件与截断记录不误算；超长内容与 HTML 按纯文本处理。
- 队列空/未知/多项/确认时变化/停止后后继接管；不默认为迁移成功，不重复取消或创建任务。
- 等待退出、等待画布同步、同步失败、目标掉线、管理员禁用、账号/路由切换时保持既有防护。
- 键盘从真实选择器打开、取消、焦点返回；窄屏不横向溢出；读屏只播报阶段变化，不逐字抢焦点。
- 连续脑图编辑仍保持实时预览；新增文字逐字显示、旧文字改写不截短、默认视角不移动。
